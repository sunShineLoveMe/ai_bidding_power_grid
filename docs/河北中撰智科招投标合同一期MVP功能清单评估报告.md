# 河北中撰智科招投标合同一期 MVP 功能清单评估报告

> 评估日期：2026-05-18  
> 合同文件：`/Users/chris/Documents/项目/AI标书项目/河北中撰智科科技有限公司-招投标合同.docx`  
> 评估对象：合同附件“系统功能清单1”中的 MVP 功能，以及其与现有 AI 标书项目的短期匹配度  
> 当前项目基础：水利行业单企业 AI 标书系统，已具备“招标文件上传解析 → AI 解读 → 大纲生成 → 正文生成 → 合规检查 → Word 导出 → 知识库/资信库/产品库 → 智能助手”的主链路

## 一、总体结论

合同“系统功能清单1”作为一期 MVP 方向整体可行，现有项目可以作为电网行业改造的基础底座，短期内具备交付一期 MVP 的条件。

但该结论有三个前提：

1. 一期必须限定为“单企业电网行业投标辅助系统”，不能扩大为 SaaS、多企业、多租户或公网商业化平台。
2. 一期验收应围绕客户提供的 5-10 份典型国网招标文件样本，不应承诺覆盖国家电网全部招标类型。
3. 系统输出应定位为“标书初稿生成 + 条款响应检查 + 风险提示”，不能承诺“完全自动生成可直接投标终稿”“全量废标风险识别”或“替代人工审核”。

如果按上述边界执行，合同约定 3 个月周期基本可支撑一期 MVP；如果按合同“合作目的”中“招标文件生成、智能审查、评标过程自动化辅助、围串标精准识别、投标决策支持”等宽泛表述理解，则明显超出当前一期能力和 3 个月交付范围。

建议结论：

> 一期 MVP 可以短期满足，但必须以“电网单企业试点版”为交付口径；合同正文中偏平台化、监管化、评标自动化、围串标识别的表述应收缩或明确为二期/远期能力。

### 3.1 短期可直接复用的能力

现有系统中以下能力已经具备较高成熟度，电网改造主要是行业内容替换和 Prompt 调优：

- 招标文件上传、解析、OCR/MinerU 状态流转；
- 招标文件结构化解读；
- 评分项、风险项、资格项提取框架；
- 分册大纲生成；
- 章节正文生成、补写和篇幅控制；
- 企业知识库、资信库、产品库；
- RAG 检索增强生成；
- 合规覆盖检查和 LLM 语义复核；
- Word 导出、目录、标题层级、图片处理；
- 智能助手；
- AI 用量与成本统计。

### 3.2 必须短期改造的能力

一期 MVP 不只是换几个页面文案，至少需要完成以下电网化改造：

1. 行业 Profile 抽象：把当前水利行业企业画像、Prompt、关键词、分册逻辑、知识库种子数据抽成可配置行业 Profile。
2. 电网 Prompt 调优：招标解读、大纲、正文、合规检查、知识库问答都需要电网行业版本。
3. 电网种子库建设：术语、标准、技术方案话术、商务响应话术、否决项样例、资质分类。
4. 电网分册结构：技术标、商务标、资格标、报价/货物清单、附件材料的章节规则。
5. 电网资料分类：企业资信库和产品库分类从水利资产改为电力供应商资产。
6. 导出模板适配：至少支持客户提供的一套 Word 模板，包括封面、目录、字体、页眉页脚、页码。
7. 阿里云单企业部署：补充部署文档、启动脚本、环境变量、安全配置、备份和日志方案。

## 四、功能清单2不应纳入一期 MVP

合同“系统功能清单2”标记为 GA，包括智能查重、全方位合规扫描、精准废标风险识别、2000+规则库、资质到期预警、千标千面防雷同、图文融合输出、多企业标书等。

这些能力不建议纳入 3 个月一期验收：

| GA 功能 | 不建议纳入一期原因 |
| --- | --- |
| 智能查重 / 多文件比对 | 需要查重算法、语料库、阈值校准和责任边界，短期不适合作为硬验收。 |
| 围串标/防雷同/千标千面 | 法律和合规敏感，容易被理解为规避监管；建议改为“文本多样化表达建议”，不要承诺规避围串标。 |
| 全方位合规扫描 | 需要长期规则库和法规知识库维护，一期只能做条款响应检查。 |
| 精准废标风险识别 | 可提示重点否决项，但不能承诺精准识别所有废标风险。 |
| 2000+规则库 | 当前没有国网 2000+规则库基础，不应写入一期验收。 |
| 资质到期预警 | 需要结构化资质台账、有效期字段、提醒机制，适合二期。 |
| 多企业标书 | 属于 SaaS/多租户能力，应放二期。 |

## 五、合同文本风险与修改建议

### 5.1 合作目的表述过大

合同正文中写到“招标文件的生成、智能审查、评标过程的自动化辅助、围串标行为的精准识别、供应商投标决策支持”。这比系统功能清单1大很多。

建议改为：

> 本项目一期建设目标为电网行业单企业投标辅助系统 MVP，围绕招标文件解析、企业资料管理、产品资料管理、RAG 辅助生成、标书初稿编制、条款响应检查和 Word 导出，提升投标文件编制效率。系统输出仅作为辅助，不替代甲方业务、法务、技术人员的最终审核。

### 5.2 “知识图谱”建议弱化

合同提到“知识图谱”，但功能清单1实际更接近“知识库 + RAG + 规则分类”。如果写成知识图谱，客户可能期待实体关系建模、规则推理、可视化图谱和法规推理。

建议改为：

> 企业知识库、行业知识库与检索增强生成能力。

### 5.3 “合规性”要明确辅助性质

建议在验收条款或功能说明中加入：

> 系统提供条款响应覆盖检查、评分项覆盖提示、重点否决项风险提示，不构成法律意见或最终合规结论。正式投标文件仍需甲方人工审核确认。

### 5.4 “源代码交付”和“知识产权归属”风险较高

当前项目已有大量通用底座能力。如果合同写成“开发源代码需提供给甲方”“项目成果知识产权由甲方拥有”，可能导致乙方既有代码、通用组件、通用 Prompt 框架、部署脚本、行业 Profile 架构都被解释为甲方独占。

建议补充：

1. 乙方在本项目开始前已拥有的通用软件平台、基础框架、通用组件、工具链、模型调用封装、通用算法、通用 Prompt 框架等仍归乙方所有。
2. 甲方享有本项目定制成果在本单位内部使用的永久授权。
3. 甲方提供的企业资料、标书样本、产品资料、业务数据归甲方所有。
4. 若甲方要求完整源代码独占或限制乙方复用，应另行约定费用和范围。

### 5.5 12 个月免费服务范围需收缩

合同写“数据、功能问题处理；软件细节功能问题调整；Bug 免费修复”。其中“数据问题处理”和“细节功能调整”容易被扩大为持续运营和新增需求。

建议明确：

- 免费维护仅限合同范围内软件缺陷修复；
- 不含新增功能、规则库大规模扩充、新招标类型专项适配、历史数据清洗、客户资料录入、模型费用、OCR费用、云资源费用；
- 超出范围按人天或补充协议计费。

## 六、一期建议验收口径

建议把 MVP 上线验收绑定到“单企业完整闭环”，而不是功能名堆叠。

| 验收项 | 建议验收标准 |
| --- | --- |
| 招标文件解析 | 客户提供的典型国网样本可上传、解析，并抽取项目概况、评分项、资格项、否决项、技术规范、附件要求。 |
| 样本适配 | 完成 5-10 份国网样本分析，形成电网字段、章节、风险分类和 Prompt 适配。 |
| 企业资料库 | 支持上传、分类、检索和引用企业资质、检测报告、业绩、授权、体系认证。 |
| 产品库 | 支持上传、管理和引用电力产品参数、检测报告、授权文件、产品图片。 |
| 大纲生成 | 可生成电网行业技术标、商务标、资格标、报价/货物清单、附件结构。 |
| 正文生成 | 可基于招标文件、企业资料、产品资料生成标书正文初稿。 |
| AI 编辑 | 支持章节级扩写、缩写、润色、风格调整等基础编辑。 |
| RAG | 解读、大纲、正文、补写和智能助手能检索企业私有资料和电网知识库。 |
| 条款响应检查 | 可提示评分项、资格项、重点否决项和关键条款的覆盖情况。 |
| Word 导出 | 可导出具备基础目录、标题层级、表格、图片、页眉页脚、页码的 Word 文件。 |
| 智能助手 | 可围绕企业资料、产品资料、招标文件进行问答。 |
| 部署运行 | 在单企业环境完成部署、启动、访问、上传、生成、导出流程。 |

## 七、3个月实施可行性评估

### 7.1 推荐排期

| 周期 | 工作重点 | 交付结果 |
| --- | --- | --- |
| 第 1-2 周 | 合同边界确认、资料收集、国网样本分析、行业 Profile 设计 | 国网字段清单、分册结构、Prompt 改造方案、资料缺口清单 |
| 第 3-5 周 | 行业 Profile、电网 Prompt、电网知识库、资信库/产品库分类改造 | 电网版解析、大纲、正文、RAG 初版可跑通 |
| 第 6-8 周 | 合规检查电网化、导出模板适配、智能助手接入、电网样本联调 | 完整主链路可演示 |
| 第 9-10 周 | 阿里云单企业部署、日志备份、安全配置、性能与长文档测试 | 测试环境上线 |
| 第 11-12 周 | 客户试用、问题修复、验收材料、培训 | MVP 验收版 |

### 7.2 资料前置条件

短期能否满足，关键取决于客户资料是否及时提供。建议合同或项目启动单中明确：

- 启动前提供企业基本信息和 Word 模板；
- 启动后 1 周内提供 5-10 份国网招标文件样本；
- 启动后 2 周内提供历史中标标书、资质清单、业绩清单、产品资料；
- 启动后 3 周内提供行业标准、常见废标情形、产品图片、资质扫描件等。

资料不到位时，乙方只能基于公开样本和通用电网知识做基础适配，生成质量和验收进度应相应顺延或降低。

## 八、二期 SaaS 的边界建议

合同上下文提到一期 MVP、二期类似 SaaS。建议明确两期差异：

| 能力 | 一期 MVP | 二期 SaaS |
| --- | --- | --- |
| 使用范围 | 单企业 | 多企业 |
| 账号体系 | 可不做或轻量本地登录 | 企业注册、登录、JWT、企业隔离 |
| 数据隔离 | 单实例物理隔离或单企业部署 | enterprise_id 全链路隔离 |
| 知识库 | 单企业知识库 | 每企业独立知识库 |
| 存储 | 单企业目录或 bucket | OSS 按 enterprise_id 分层 |
| 计费 | 用量统计 | 按企业用量统计和计费准备 |
| 部署 | 单企业阿里云/私有化 | 阿里云 SaaS 架构、域名、HTTPS、备案、备份 |
| 运维 | 项目级维护 | 平台级运营后台、企业管理、日志审计 |

不建议在一期引入多租户，否则会同时面对“行业迁移 + 多租户 + 阿里云生产部署”三类风险，短期交付不稳定。

## 九、最终判断

### 9.1 是否可以短期满足

可以，但应定义为“有边界的一期 MVP 可满足”。

现有项目的主链路成熟度足够支撑电网行业改造，合同功能清单1中大部分能力都有可复用基础。真正新增的不是底层系统，而是电网行业适配、资料体系、Prompt、规则分类、导出模板和部署工程化。

### 9.2 最大风险

1. 合同正文目标过大，可能让客户把 GA 能力理解为一期承诺。
2. 国网样本和客户企业资料不到位，会直接影响生成质量和验收。
3. “合规检查”“废标风险”“围串标识别”等词语风险较高，必须弱化为辅助提示。
4. 源代码交付和知识产权归属需要保护乙方既有平台底座。
5. 阿里云部署要明确是单企业测试/试点部署，不是高可用 SaaS 平台。

### 9.3 建议对外口径

> 一期交付电网行业单企业投标辅助系统 MVP，重点完成国网招标文件解析、企业资信库、产品库、电网知识库、RAG 辅助生成、标书初稿编制、条款响应检查、智能助手和 Word 导出。系统用于提升标书编制效率和资料复用能力，正式投标前仍需人工审核。多企业 SaaS、完整规则库、智能查重、资质到期预警、精准废标识别等能力建议放入二期或后续专项建设。
