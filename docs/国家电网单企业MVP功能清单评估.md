# 国家电网单企业投标辅助系统 MVP 功能清单评估

## 一、评估背景

本评估基于现有 AI 标书系统能力，以及表格中列出的国家电网投标场景改造功能清单进行判断。表格中标记为 `GA` 的功能暂不纳入本次 MVP 范围，仅评估 `MVP` 部分。

本阶段建议定位为：

> 国家电网单企业投标辅助系统 MVP，目标是完成国网招标文件解析、企业资料管理、产品资料管理、RAG 辅助生成、标书初稿编制、基础条款响应检查和 Word 导出，帮助企业提升投标文件编制效率，但不替代人工投标审核。

## 二、总体结论

只看 MVP 功能清单，整体方向是合理的，适合作为单企业试点版或一期交付范围。

但需要明确边界：

- MVP 应聚焦“国网投标主流程跑通”，不应承诺成熟商业版能力。
- MVP 可以生成标书初稿和风险提示，但不能承诺完全替代人工审核。
- MVP 可覆盖客户提供的典型国网招标样本，不应承诺覆盖国家电网全部招标类型。
- MVP 可做基础条款响应检查，不应承诺全量合规审查、废标规则库或法规知识图谱。
- MVP 建议以 Word 导出为核心，PDF、复杂排版和终稿格式仍需人工复核。

## 三、MVP 功能合理性评估

| MVP 功能 | 评估结论 | 建议交付边界 |
| --- | --- | --- |
| 招标文件智能解析 | 合理，建议保留 | 支持 PDF、DOCX、TXT、MinerU/OCR 和原生解析，重点适配国网招标文件结构和关键字段。 |
| 国网招标文件样本分析 | 必须保留 | 收集并分析客户提供的典型国网招标文件，拆解项目结构、评分项、资格要求、否决项和技术规范。 |
| 电力行业术语与知识库 | 合理，但需控制范围 | 建立输变电、配网、物资、施工、运维、服务类基础知识库；不承诺完整行业知识图谱。 |
| 电力分册结构配置 | 必须保留 | 将现有技术标、商务标、资格文件、报价/货物清单、附件结构改造为电力投标场景适配结构。 |
| 企业资信库 | 合理，建议保留 | 支持企业证照、检测报告、业绩、授权、体系认证等资料上传、分类、检索和引用。 |
| 产品库 | 合理，建议保留 | 支持电缆、开关柜、变压器、互感器、保护装置、通信设备、施工服务等产品资料管理。 |
| OCR 信息提取 | 合理，建议保留 | 自动识别招标人、项目概况、评分标准、资质要求、废标条款等关键信息；扫描件效果受 OCR 质量影响。 |
| 章节大纲生成 | 合理，建议保留 | 复用现有大纲生成框架，重点完成国网分册结构和章节规则电力化。 |
| 标书正文生成 | 合理，建议保留 | 生成商务标、技术标、服务方案、实施计划等正文初稿；正式提交前必须人工复核。 |
| 合规覆盖检查 | 合理，但需降级表述 | MVP 阶段建议定位为“条款响应检查”和“重点否决项提示”，不作为最终合规结论。 |
| AI 辅助编辑 | 可保留轻量版 | 支持扩写、缩写、润色、正式化表达、风格调整等基础编辑能力。 |
| RAG 检索增强生成 | 合理，建议保留 | 结合企业私有知识库、历史标书、资质材料、产品资料生成更贴合企业实际的标书内容。 |
| 排版调优 | 合理，但需明确边界 | 支持 Word 标题层级、目录、表格、图片、页眉页脚、字体等基础格式；复杂终稿仍需人工校对。 |
| 多格式导出 | 建议收缩 | MVP 建议以 Word 导出为主；PDF 可作为可选转换能力，不建议作为核心验收项。 |
| 阿里云部署 | 必须保留 | 建议按单企业私有化部署或轻量生产部署设计，不做多租户和高可用集群。 |
| 智能助手 | 可保留轻量版 | 保留悬浮智能问答助手，用于企业知识库问答、资料检索和投标编制辅助。 |
| 使用范围 | 合理，必须明确 | 本阶段仅支持单企业使用，不支持多企业、多租户、多组织权限。 |

## 四、建议纳入一期 MVP 的交付范围

建议一期 MVP 明确为以下内容：

| 模块 | 交付内容 |
| --- | --- |
| 招标文件解析 | 支持国网招标文件上传、解析、OCR、结构化抽取和解析状态跟踪。 |
| 国网字段抽取 | 抽取项目概况、资格要求、评分项、否决项、技术规范、商务条款、附件要求。 |
| 国网样本适配 | 基于客户提供的典型国网样本完成 Prompt、字段、分册、规则适配。 |
| 电力分册结构 | 支持技术标、商务标、资格文件、报价/货物清单、附件材料等投标文件结构。 |
| 企业资信库 | 支持证照、授权、检测报告、体系认证、业绩材料等资料管理。 |
| 产品库 | 支持产品型号、技术参数、检测报告、授权文件、产品图片等资料管理。 |
| 电力基础知识库 | 建立初版电力行业术语、方案话术、服务响应、技术规范知识库。 |
| RAG 辅助生成 | 解读、大纲、正文、补写和智能助手调用企业资料与电力知识库。 |
| 标书大纲生成 | 自动生成符合国网投标结构的章节大纲。 |
| 标书正文生成 | 自动生成标书正文初稿，支持人工编辑和 AI 辅助改写。 |
| 条款响应检查 | 检查关键条款、评分项、资格要求和重点否决项是否被响应。 |
| Word 导出 | 支持投标文件 Word 导出，包含基础标题、目录、表格、图片和页眉页脚格式。 |
| 智能助手 | 提供悬浮式问答入口，支持知识库检索和资料问答。 |
| 用量与成本统计 | 统计模型调用、Token、人民币预估成本和项目级调用明细。 |
| 阿里云部署 | 完成单企业部署、基础安全配置、上传限制、日志和备份说明。 |

## 五、建议暂不纳入 MVP 的能力

以下能力虽然对成熟产品有价值，但不建议放入本阶段 MVP 验收范围：

| 能力 | 原因 |
| --- | --- |
| 全量国网规则库 | 国网招标类型复杂，规则建设需要长期样本积累。 |
| 完整废标风险识别 | 可以提示重点风险，但不能承诺精准识别所有废标项。 |
| 法规知识图谱 | 建设成本和维护成本较高，不适合一期 MVP。 |
| 智能查重 | 涉及查重语料、算法准确率和合规责任，建议后续单独规划。 |
| 千标千面防雷同 | 容易引发合规和串标敏感表述，建议谨慎处理。 |
| 多企业 / 多租户 | 本阶段定位单企业，不应扩大为平台型系统。 |
| 自动复杂制图 | 架构图、甘特图、流程图自动生成可作为增强能力，MVP 不建议强承诺。 |
| 高可用集群部署 | 单企业 MVP 建议轻量部署，不做复杂高可用架构。 |
| 自动资质到期预警 | 需要完整资质台账、日期字段和提醒机制，建议后续增强。 |
| 终稿完全自动排版 | Word 格式可基础规范化，但正式投标文件仍需人工最终确认。 |

## 六、关键风险点

### 1. 国网场景复杂度风险

国家电网招标文件覆盖物资、施工、服务、运维、框架协议、资格预审、技术规范书、专用资质、产品检测报告等多类场景。

MVP 应限定为“覆盖客户提供的典型样本类型”，不建议表述为“覆盖全部国网招标场景”。

### 2. 样本数量和质量风险

国网样本分析是本次改造的核心输入。如果客户提供的样本数量少、类型单一或资料不完整，系统对其他标书类型的适配效果会受影响。

建议在实施前明确：

- 样本由客户提供。
- 样本应包含技术规范、评分办法、资格要求、否决条款、投标文件格式等关键部分。
- 超出样本范围的新类型招标文件，可能需要追加适配。

### 3. 合规和废标风险

系统可以辅助识别条款响应、评分项覆盖、资格要求和重点否决项，但不能替代投标负责人、商务人员、法务或技术专家审核。

建议统一使用以下表述：

> 系统提供条款响应追踪和风险提示，最终投标文件仍需人工审核确认。

### 4. 生成内容准确性风险

AI 生成内容依赖招标文件解析结果、企业资料质量、产品资料完整度和 Prompt 约束。若企业资料缺失，系统可能只能生成占位内容或通用表达。

建议保留：

- 人工复核提示
- 缺失资料提醒
- 占位符机制
- 条款响应检查

### 5. 排版和导出风险

正式投标文件对页眉页脚、目录、页码、章节编号、表格、图片、附件顺序要求较高。

MVP 可支持基础 Word 导出，但不建议承诺所有招标文件格式完全自动符合要求。

### 6. OCR 和长文档处理风险

扫描版 PDF、图片型附件、大体积文件会增加 OCR 成本、解析耗时和失败概率。

建议在系统中保留：

- 解析状态
- 失败重试
- OCR 成本统计
- 人工上传解析结果入口

### 7. 部署和运维风险

本阶段建议按单企业私有化部署设计，不建议扩大为多企业平台。

部署时需要明确：

- 云资源费用归属
- 模型调用费用归属
- OCR 调用费用归属
- 数据备份策略
- 运维支持边界

## 七、建议验收口径

建议验收时围绕“可用闭环”而不是“完全自动投标”：

| 验收项 | 建议口径 |
| --- | --- |
| 招标文件解析 | 客户提供的典型国网样本可完成上传、解析和关键信息抽取。 |
| 大纲生成 | 可生成符合电力投标结构的技术、商务、资格、报价/货物清单、附件章节。 |
| 正文生成 | 可基于招标文件和企业资料生成标书正文初稿。 |
| 企业资料引用 | 可从企业资信库、产品库、知识库中检索并辅助生成内容。 |
| 条款响应检查 | 可提示关键条款、评分项、资格要求和重点否决项响应情况。 |
| Word 导出 | 可导出具备基础格式的 Word 标书文件。 |
| 智能助手 | 可围绕企业资料和投标文件进行问答。 |
| 部署运行 | 可在单企业环境完成部署、启动、访问、上传、生成和导出流程。 |

## 八、建议对外表述

建议对中间人或客户采用以下表述：

> 本阶段建设目标是交付国家电网单企业投标辅助系统 MVP，重点完成国网招标文件解析、企业资料库、产品库、知识库、RAG 辅助生成、标书初稿编制、条款响应检查和 Word 导出。系统用于提升投标文件编制效率和资料复用能力，正式投标前仍需人工审核确认。

不建议使用以下表述：

- 自动生成可直接投标的终稿。
- 自动识别所有废标风险。
- 覆盖国家电网全部招标类型。
- 保证标书完全合规。
- 自动替代商务、技术、法务审核。
- 支持多企业、多租户平台化使用。

## 九、最终建议

该 MVP 清单可以作为一期建设方向，但需要在方案或合同中明确：

- 本阶段只做单企业。
- 本阶段以客户典型国网样本为适配范围。
- 本阶段输出标书初稿和辅助检查，不替代人工审核。
- 本阶段以 Word 导出为核心。
- 本阶段不包含 GA 功能。
- 后续可在二期继续扩展规则库、查重、资质匹配、复杂排版、多企业和更完整的合规能力。
