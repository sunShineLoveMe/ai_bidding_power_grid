# 标书前导确认页与正文导出一致性评审记录（2026-06-14）

## 结论

前导页仍有必要，但不应替代现有的章节目录编辑和正文编辑。

现有系统已经支持：

- 招标文件解析后自动生成章节目录；
- 用户自定义新增、删除、调整章节目录；
- 用户修改章节标题；
- 章节目录确认后生成正文；
- 用户在正文编辑器中修改正文。

因此，前导页的定位不应是“再做一个大表格让用户填写”，而应是生成正文前的“投标信息确认/变量收口页”。它解决的是跨章节重复变量和客户决策信息的确认问题，例如分标包号、货物清单、报价、交货期、质保期、投标保证金、授权代表、签章日期等。

## 为什么仍然需要前导页

如果没有前导页，系统会在正文生成后留下大量 `【待补充】`：

- 同一个变量会在多个章节重复出现，例如包号、投标日期、授权代理人姓名；
- 操作员需要在正文里逐处查找和修改，容易漏改；
- 后续导出 Word 时，很难判断“缺口是客户没提供”还是“已经提供但没有同步到所有章节”；
- 正文编辑适合处理章节表达，但不适合管理全局投标变量。

前导页应把这类信息在生成正文前集中收口。正文编辑器保留给用户做章节级内容调整，而不是承担全局变量管理。

## 推荐产品形态

前导页建议做成系统内的分模块确认向导，不建议直接把 649 行 CSV 给操作员填写。

| 模块 | 主要字段 | 来源 |
| --- | --- | --- |
| 项目信息 | 项目名称、招标编号、分标编号、包号、包名称 | 招标文件自动解析 + 用户确认 |
| 货物清单 | 产品名称、规格型号、数量、单位、交货地点 | 招标文件/货物清单自动解析 + 用户确认 |
| 商务报价 | 总价、分项单价、税率、大写金额 | 客户内部报价决策 |
| 投标承诺 | 交货期、质保期、投标有效期、售后响应时间 | 招标要求 + 客户承诺 |
| 保证金信息 | 金额、形式、凭证、基本账户 | 财务/商务确认 |
| 授权签章 | 授权代表、身份证号、联系方式、签署日期 | 法务/投标经办确认 |
| 项目团队 | 项目负责人、质量负责人、售后联系人 | 客户内部指派 |
| 附件确认 | 营业执照、证书、业绩、检验报告是否采用 | 企业库自动带出 + 用户确认 |

## 风险与边界

- 前导页不能替代章节目录编辑；章节结构仍应允许用户自定义。
- 前导页不能替代正文编辑；正文编辑后的内容必须始终优先进入导出。
- 前导页不能让模型编造报价、保证金、授权签章、最终承诺等客户决策信息。
- 不同招标场景需要不同变量 schema，不能用一个固定 Word 模板硬套所有场景。
