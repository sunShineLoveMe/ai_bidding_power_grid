# 泰昌技术标/商务标模板与招标要求融合需求调研稿

> 文档状态：已吸收 2026-07-12 内部评审修正，待客户/产品/技术联合确认
> 编制日期：2026-07-11
> 修订日期：2026-07-13
> 试点主体：河北泰昌电力器材科技有限公司
> 本轮边界：仅调研、盘点、差距分析和需求定义；不修改业务代码，不入库，不调整现网 RAG，不生成新的正式投标文件。

---

## 1. 调研结论摘要

客户反馈成立，并且不是单纯的“字体、页边距或图片多少”问题，而是当前系统交付模型与真实投标人成稿模型不一致：

- 当前系统主要按“AI 长正文 + 少量自动配图”生成技术标和商务标。
- 客户认可的新疆成稿实际是“招标规定表单 + 参数逐项响应 + 评审要素组织 + 大量证据附件页”。
- 泰昌新提供的《技术补充文件》和《商务补充文件》，不只是资料包，还同时承载“招标条款历史落地样本 + 泰昌事实与证据编排稿”两层价值。
- SL265A 原始招标文件验证表明，第六章已经明确到技术偏差表、技术参数表、生产装备、制造工艺、认证证书、检测报告等具体条目；主体骨架主要来自招标制度要求，并非新疆或泰昌某份稿件的审美偏好。
- 招标文件全套要求及澄清补遗是每个项目目录、格式、必填表单、上传端口和否决门禁的最高优先级依据。新疆成稿和泰昌补充文件只作为历史落地样本，不得直接覆盖当次招标要求。

因此，建议将后续能力定义为：

> 以当次招标文件生成“项目级投标编制规则”，与两份固化的泰昌历史稿做确定性结构差异对照，以泰昌一手资料填充事实、参数、表单和证据页，以泰昌历史稿和新疆稿参考分册落地与版式，以当前长正文能力生成必要论述内容，最终形成“正文、表格、响应项、附件证据页”混合编排的技术标/商务标。

## 2. 需求背景与业务目标

### 2.1 业务背景

泰昌投标人员已经明确：

1. 当前系统生成的技术标、商务标与其实际预期明显不符。
2. 客户认可新疆技术标/商务标的分册目录、章节组织、表单与正文/附件布局，但不认可其他企业的图片、参数、证书、业绩和事实。
3. 客户按招标文件与新疆成稿的思路，又提供了泰昌自身的技术/商务补充文件。
4. 客户强调每份招标文件已规定投标文件组成、表单格式和部分正文要求，未按要求编制可能直接导致否决投标。

### 2.2 核心业务目标

- 把“能写长文”升级为“能按招标文件编制完整投标分册”。
- 确保每个项目的技术标/商务标目录可追溯到招标文件原始条款。
- 确保泰昌证书、报告、工艺、设备、人员、业绩等证据可按章节成组编排，而不是随机插入少量图片。
- 保留当前系统已成熟的文字型正文生成能力，不做推倒式重构。
- 建立“否决风险优先”的编制与导出前检查机制。

### 2.3 非目标

- 不把新疆其他投标人的任何事实或图片复制为泰昌事实。
- 不把泰昌电缆保护管资料默认用于架空绝缘导线项目。
- 不把任何一份参考目录硬套到全部省份、批次、物料和分标。
- 不建设多企业、任意模板上传或通用语义相似度平台；本期只处理泰昌及两份已固化历史稿。
- 不把“模板变量替换”扩展为任意 DOCX 的全自动原位改写；本期仅评估固定表单和稳定版式块的有限复用。
- 不在本轮调研中执行数据库入库、代码改造或正式文件导出。

## 3. 用户角色与核心痛点

| 角色 | 核心任务 | 当前痛点 | 需要的系统结果 |
| --- | --- | --- | --- |
| 泰昌投标编制人员 | 按招标文件完成技术标/商务标 | 系统输出像通用方案，不像真实投标分册 | 招标目录原样落地，表单、响应、证据页完整编排 |
| 资料管理员 | 管理证书、报告、图片、合同、人员资料 | 资产虽已入库，但很难判断应放在哪个章节、是否完整 | 按产品/证据类型/报告/页序形成证据包 |
| 项目负责人 | 把关否决风险、章节和材料完整性 | 难以确认系统是否真正按招标文件执行 | 要求来源、适用条件、完成状态和阻断原因清晰可查 |
| 审核人员 | 检查偏差、保证值、签章、附件 | 容易出现误填“无偏差”、证据过期或跨产品误用 | 项目级合规清单和人工复核门禁 |

### 4.1.1 《技术补充文件》产品与参数可用性二次审计

《技术补充文件》具有较高的泰昌资产线索价值，但不能整份直接作为泰昌企业事实入库。文件中同时出现 `SL265 / 1kV架空绝缘导线-新疆` 项目抬头、PVC 复合材料管技术规范，以及 MPP、CPVC、N-HAP、UPVC 等泰昌电缆保护管能力资料，说明其属于多来源编排稿，必须在章节、表格和证据页层面判断来源与适用产品。

| 内容 | 可用性结论 | 目标库/处置 |
| --- | --- | --- |
| MPP 报告 `2024100312005501712`、CPVC 报告 `2024100312005501713` | 可用，但系统已有 36 行结构化参数及正式证据 | 产品库保留既有主记录；本 Word 仅增加来源和章节映射 |
| N-HAP 报告 `2024400312005505333`、UPVC 报告 `2025200312005503479` | 当前仅能确认报告索引，尚不能确认完整参数 | 作为 `review_only` 线索；取得泰昌原始完整报告后再进入产品参数重抽取 |
| MPP/CPVC 多口径产品清单 | 可用于发现候选产品范围，不能证明所有规格均有检验报告支持 | 产品库候选规格；状态为 `candidate_product_spec`，不得自动用于正式保证值 |
| MPP、CPVC、N-HAP、PE 工艺说明 | 可作为企业知识候选，但可能包含通用套话、错别字或历史工艺 | 企业知识库 `knowledge_only`；由泰昌技术人员确认后再批准复用 |
| 六类试验设备、现场图片和校准信息 | 有价值，但与现有设备台账、图片和 2026 年校准证书重复 | 产品库按设备型号、管理编号和证书号归并，较新原始证据优先 |
| 三体系证书 | 可进入资信核验，其中职业健康安全证书 `626023S10219R0` 已于 2026-06-18 到期 | 资信库保留版本和有效期；过期证书禁止正式引用，等待续证 |
| 人员、电话、地址和证件信息 | 仅限受控使用 | 资信库 `restricted`，不进入普通 RAG 和自动 DOCX |
| “全部响应”“无偏差”“完全符合要求” | 仅是特定项目响应，不是产品参数或稳定企业事实 | 项目历史档案；每次按新招标要求重新判断 |

参数值必须区分 `tender_requirement`、`bidder_guarantee`、`inspection_result`、`candidate_product_spec` 和 `generic_response`。只有能够回溯泰昌原始文件、报告编号和来源页的检验结果或已确认保证值，才能进入正式参数层。

## 5. 核心原则与权威优先级

### 5.1 五级优先级

```text
当次招标文件全套内容、澄清和补遗中的强制要求
> 当前项目的分标/包/物料/资格模式/保证金等条件
> 泰昌原始企业事实、结构化参数和已审核证据资产
> 历史落地样本的章节映射与版式经验（泰昌历史稿优先，新疆稿仅作参考）
> 系统通用模板和 AI 自由生成
```

这里的“历史落地样本”只表示结构参考角色相近，不表示资料权限相同：泰昌稿中的企业事实经溯源审核后可作为泰昌事实候选；新疆稿始终只能 `reference_only`。

### 5.2 来源边界

| 来源 | metadata 定位 | 允许用途 | 禁止用途 |
| --- | --- | --- | --- |
| 泰昌原始资料 | `source_domain=enterprise_fact` | 支撑泰昌事实、参数、资质、设备、业绩和正式证据页 | 未核对原始来源、产品适用性或有效期时直接正式使用 |
| 泰昌技术/商务补充文件 | 结构层：`source_domain=reference_template`；可追溯事实层：`source_domain=enterprise_fact` | 结构层用于章节映射和编排；事实层仅在回溯原始资料并审核后使用 | 将整份 Word 无差别视为已核验企业事实，或把项目专属承诺沿用到新项目 |
| SL265A 招标文件包 | `source_domain=tender_requirement` | 目录、格式、技术要求、评审要素、否决规则 | 作为泰昌企业事实 |
| SL2655 新疆 MPP 招标文件包 | `source_domain=tender_requirement`, `province=新疆`, `batch_no=SL2655`, `material_category=电缆保护管MPP`, `qualification_mode=prequalification` | 资格预审继承、允许补充范围、章节适用状态、技术参数、货物清单、合同约束和文件作用域 | 不得作为泰昌产品事实、检验报告或历史投标成稿；不得据此认定泰昌具备φ200×14供货能力 |
| 新疆技术/商务成稿 | `source_domain=reference_template`, `reference_only=true` | 分册结构、版式、编号、证据页组织方式 | 作为泰昌事实、参数、图片、业绩或证书 |

### 5.3 “稳定骨架 + 项目变动量”模型

本期不再把目录生成理解为“招标规则和参考风格二选一”，而是拆成三类可审计变动：

| 变动类型 | 典型内容 | V1 处理方式 |
| --- | --- | --- |
| 招标规定与条件变动 | 必选/条件/禁止章节，资格预审、保证金、评审要素、否决项 | 每个项目从当次招标文件全套内容重新判定，历史结论不得直接沿用 |
| 企业事实与证据变动 | 产品规格、参数、证书编号、金额、日期、人员、报告和附件 | 从已审核泰昌资料中按物料、规格、有效期和章节匹配 |
| 表单、版式与提交变动 | 原样表格、签章位、分页、文件类别、上传端口 | 招标原样优先；固定表单和稳定版式块可有限采用 `template_docx`，不得由 AI 改写 |

两份泰昌历史稿只在本版首次建设时完成一次结构抽取和来源标注。日常创建项目仅将当次招标结构与这两份固定骨架做标题、编号、表单名称和条件状态的确定性对照，输出新增、删除、名称变化、顺序变化和条件变化；不建设跨企业、跨行业的通用相似度引擎。

## 6. 招标文件强制要求与否决风险

### 6.1 样本批次已识别的高风险要求

| 类别 | 招标原要求摘要 | 系统需求 |
| --- | --- | --- |
| 技术参数逐项响应 | 必须填写具体数值等实质内容，不得只写“响应/完全响应/按招标文件执行” | 参数表应做字段级完整性检查；空值或笼统响应应阻断正式导出 |
| 偏差表 | 所有偏离应在指定偏差表列明；未列明则视为未提出偏离 | 不得在无数据依据时自动写“无偏差”；需建立要求值-保证值-偏差结论链路 |
| 第六章格式 | 有格式的文件必须按格式编制，实质性修改或未按要求签署可视为无效 | 原样表单应优先进入 `template_docx`/结构化表单渲染，不应由 AI 改写表头、列和声明 |
| 投标文件组成 | 价格文件按包、商务/技术文件按分标制作，并按指定端口上传 | 项目模型必须区分“包级价格册”和“分标级技术/商务册” |
| 资格预审复用 | 预审材料已是投标文件一部分，本次仅允许按要求更新/补充；重复提交部分可不予评审 | 章节应支持 `inherited_from_prequalification` / `supplement_allowed` / `update_required` / `not_applicable` 状态，不得无差别贴全量资料 |
| 章节存在但本批不适用 | SL2655 第六章保留生产装备、检测设备、制造工艺、认证证书、人员和检测报告等格式，但明确标注“本批次不适用” | 必须把“章节来源”和“当前项目状态”分开；存在于第六章不等于本项目必须输出 |
| 分标/包作用域 | SL2655 技术/商务文件主要按分标编制，价格与货物清单按包处理，同规格同固化 ID 报价需一致 | 规则必须记录 `rule_scope=batch/lot/package`、`submission_scope=by_lot/by_package` 和 `volume_type` |
| 规格级覆盖 | SL2655 要求 MPP φ200×14、断裂伸长率≥200%；泰昌现有报告为φ250×22、断裂伸长率实测176% | 产品族相同不能视为覆盖；应输出 `exact_match/partial_match/mismatch/unknown` 并在不满足时阻断正式导出 |
| 资料真实性 | 虚假资格、业绩、验收、擅改技术要求均可否决 | 每个证据块必须保留原始文件、页码、所有者、产品和审核状态 |
| 项目条件 | 本批“免收投标保证金” | 商务补充文件中的保证金/保险章节必须在本项目自动标为不适用，不得照抄入册 |
| 人员关系说明 | 未如实提交与国网系统人员关系说明将被否决 | 应为商务标项目级必填表，不能只靠通用正文代替 |
| 电子文件与签章 | 技术/商务完整文件上传辅助系统，格式页的签字/盖章要求须执行 | 系统仅生成占位与待办；签章图片不得未授权自动插入 |
| 文件大小/图片压缩 | 无证明材料处尽量使用可编辑文字；图片建议黑白、150/96ppi，8-10 张 A4 图约 1MB | 不应简单“图越多越好”；应在清晰可读、文件体积和正式证据完整性之间取平衡 |

### 6.2 规则产物要求

每个项目解析后应产出项目级《投标编制规则清单》，至少包含：

- 规则 ID、原文件、章节/表格/页码、原文摘要；
- 适用分册、适用分标/包/物料；
- `required` / `conditional` / `inherited_from_prequalification` / `supplement_allowed` / `update_required` / `not_applicable` / `forbidden` / `reference_only`；
- `rule_scope=batch|lot|package`、`submission_scope=by_lot|by_package`、`volume_type=price|business|technical`；
- 是否有固定格式、是否必须结构化填写、是否需要签章；
- 关联评分项、否决级别、导出前检查器；
- 人工确认状态及确认人。

## 11. 功能需求

### FR-01 招标文件规则抽取

- 识别第六章投标文件组成表、表单、附注、上传端口。
- 同时抽取投标人须知、评标办法、技术规范和澄清补遗中的条件与否决项。
- 生成可人工审核的项目级规则，不允许未经审核的低置信规则直接作为否决阻断依据。

### FR-02 目录权威合并与固定骨架差异对照

- 招标文件明确章节作为必选骨架。
- 项目条件决定条件章节是否出现。
- 评分表动态生成“评审要素补充文件”的子目录。
- 当次招标结构与两份固定泰昌历史骨架按标题、编号、表单名称和条件状态做确定性对照，输出新增、删除、名称变化、顺序变化和条件变化。
- 泰昌历史稿优先补充未明确的落地层级；新疆稿仅补充版式和证据页组织经验，二者都不能创造不适用章节。
- V1 不提供跨企业模板检索、语义相似度百分比或用户上传任意历史模板功能。

### FR-03 原样表单与结构化填充

- 技术/商务偏差表、投标人基本情况表、人员关系说明、生产装备等格式优先保留原表头、合并单元格、声明和签章位。
- 原样表单未填字段进入待办清单，不得由模型自动编造。
- 表单应支持项目级版本和来源哈希，招标补遗更新后可识别已过期表单。

### FR-04 技术参数与点对点应答

- 按固化 ID、技术规范编码、物料编码、规格生成响应对象。
- 优先从泰昌结构化参数和对应检验报告填充投标人保证值。
- 不可确定的参数必须保留为待确认，不得用“完全响应”替代具体值。
- 生成后应进行位号、单位、范围、上下限、报告号和来源页校验。

### FR-05 泰昌证据包

- 以“原始文件”而不是“单张图片”为基本单元管理证据。
- 记录证据包类型、原文件、页数、页序、完整性、产品、有效期、敏感级别、可用分册和推荐章节。
- 支持“整包插入”、“指定页范围”、“仅作文本事实来源”三种策略。
- 检验报告、证书、审计报告、合同和查询报告默认按原页序整页导出，不使用 MinerU 局部切图。

### FR-06 产品适用性门禁

- 资产、参数、工艺、检验报告、设备和证据包都要带产品族/物料/规格适用性。
- 架空绝缘导线项目必须阻断 CPVC/MPP/N-HAP/UPVC 电缆保护管事实。
- 不能仅在 AI prompt 中做阻断，还要在候选资产、表格填充、目录、导出 manifest 和正式检查中阻断。

### FR-07 分册证据编排

- 每个章节允许设置为“正文为主、表格为主、图文证据、整页附件、混合”。
- 证据页按文件和页序编排，支持拖拽调整，但人工调整不得破坏报告完整性。
- 附件页不在正文显示内部评分、检索理由、资产路径或 API URL。

### FR-08 项目级完整性与否决预检

- 按招标要求展示“已完成/待确认/缺失/不适用/被禁止”。
- 对固定表单缺失、保证值空白、偏差未确认、人员关系表缺失、年份不齐、证书过期、误用产品等进行阻断。
- 区分“高风险警告”与“正式导出阻断”，并显示原招标条款。

### FR-09 DOCX/PDF 输出

- 优先使用当次招标文件可编辑 Word 格式；稳定表单和版式块可有限使用两份固定泰昌历史稿的 `template_docx` 映射；无可用结构时再回退正式通用版式。
- 保留正式封面、目录、连续页码、分页、表格、横向节和附件页。
- 支持大量证据页时的分批渲染、图片压缩、失败重试、完整性 manifest 和体积预估。
- 最终上传的双层 PDF 需另做可搜索文本层、图像层、字体、页码、文件完整性验证。

### FR-10 导出审计

每次正式导出至少记录：

- 项目/分标/包/物料/模板/招标文件版本；

## 13. 交互流程需求

### 13.1 推荐流程

1. 创建项目，上传完整招标文件包、澄清、技术规范书和货物清单。
2. 系统生成《投标编制规则清单》，并与两份固定泰昌历史骨架做确定性结构差异对照。
3. 投标人员确认新增、删除、名称变化、顺序变化、条件章节和固定格式，形成技术/商务标目录。
4. 系统按已确认目录、产品和规格匹配泰昌事实、结构化参数和证据包。
5. 每章显示正文、表单、参数、证据页和缺口。
6. 用户完成待确认保证值、偏差、授权、签章、年份、证书有效期等事项。
7. 执行正式导出预检；存在否决级问题时阻断。
8. 真实导出 DOCX，刷新目录/页码，转换并校验双层 PDF。

### 13.2 关键页面

- 招标要求解析与审核页。
- 技术标/商务标项目目录页。
- 参数响应与偏差核对页。
- 泰昌证据包管理页。
- 章节内容块编排页。
- 完整性/否决风险检查页。
- 导出预览与审计报告页。

## 14. 非功能需求

| 类别 | 需求 |
| --- | --- |
| 准确性 | 招标强制规则不得仅依赖 LLM 自由理解；表格、编号、条件和否决项应结构化 |
| 可追溯 | 每个章节、表格、参数和证据页可回溯至原文件和页码 |
| 兼容性 | 保留现有标准正文型导出；新能力作为项目/分册/章节级策略，不破坏其他项目 |
| 性能 | 支持 300-600 页、300-500 个媒体的 DOCX 生成；大文件导出应可续传/重试并显示进度 |
| 稳定性 | 单页证据失败不得静默遗漏；必须在 manifest 记录并阻断正式交付或需人工豁免 |
| 解析兼容性 | 遇到缺失 `w:tblGrid` 等非标准 DOCX 表格时应降级走 XML 结构解析并标记告警；不得静默丢表或直接判定为空文档 |
| 安全 | 身份、社保、银行、财务、签章资料按租户、项目和角色授权；导出操作留审计日志 |
| 可维护性 | 规则、目录、表单、版式、证据策略分层，不将某省或某批次规则硬编码到通用逻辑 |

## 15. MVP 范围与分期建议

### P0：项目规则与泰昌证据盘点

1. 对 SL265A 架空绝缘导线包做目录/格式解析和跨产品阻断评审。
2. 对 SL2655 新疆 MPP 包做资格预审继承、章节适用状态、分标/包作用域、参数要求和资料覆盖的结构化评审。
3. 对两份泰昌补充 Word 同时做章节/表单结构 inventory、来源属性标注、原始文件回溯、页级去重和证据包完整性盘点。
4. 将 SL265A、SL2655 当次结构分别与两份泰昌固定骨架做确定性差异对照，形成 V1 对照规则，不建设通用相似度模块。
5. 产出“已有/新增/冲突/缺失/禁止”五类资产清单，以及 SL2655 φ200×14 的规格覆盖缺口清单。
6. 由泰昌投标人员确认章节来源、目录差异、高风险规则、资格预审状态和规格缺口。

### P1：项目级分册骨架与表单

1. 按招标规则生成技术/商务目录，支持必选/条件/禁止章节，并显示相对泰昌固定骨架的差异。
2. 先落地技术/商务偏差表、技术特性参数表、人员关系说明、基本情况表；仅这些固定表单和稳定版式块评估 `template_docx` 定位填充。
3. 支持当前正文生成作为 `narrative` 块插入。

### P2：证据包与图片附件型导出

1. 实现报告/证书/合同/审计报告的文件级证据包。
2. 实现按原始页序的整包导出和章节编排。
3. 实现大文件体积、图片清晰度、页序、敏感性和产品适配门禁。

### P3：真实投标交付闭环

1. 两份固定泰昌历史稿和招标原样表单的有限 Word 定位填充，不支持任意模板上传。
2. 双层 PDF 导出和上传前检查。
3. 项目规则、资产、表单、偏差、签章和导出审计闭环。

## 16. 验收标准

### 16.1 目录与规则

- 技术/商务标一级及核心二级目录与当前项目第六章一致率 100%。
- 每个必选/条件/禁止章节均有招标原文来源。
- 本批“投标保证金”不进入正式商务标目录。
- SL2655 中生产装备、检测设备、制造工艺、认证证书、人员和检测报告等“格式存在但本批不适用”的章节不得进入正式目录。
- 价格文件按包、技术/商务文件按分标的作用域判定正确；不得把价格文件历史复用扩展为替代国网投标工具。
- 不出现施工类通用目录，不出现招标文件未要求的随意大章。

### 16.2 内容与数据

- 技术参数不允许用笼统“完全响应”代替要求的具体保证值。
- 无可追溯依据的保证值、偏差结论、产能、服务时限、人员和业绩数值不得自动填充。
- 固定格式表单的表头、列、声明和签章位不得被实质改写。
- 每个资格/报告/证书结论都能回溯原文件与页码。
- SL2655 φ200×14 与泰昌现有 φ250×22 报告应判定为规格不匹配；断裂伸长率要求≥200%与泰昌现有实测176%应形成参数缺口，不得自动填入保证值。
- 技术补充文件中的 MPP/CPVC 既有报告不得生成重复参数行；N-HAP/UPVC 未取得原始完整报告前不得生成正式检验值。
- 历史产品清单规格不得自动显示为“已有检验报告覆盖”；笼统“完全响应”不得转换为保证值或无偏差结论。
- 过期体系证书和旧版校准日期不得覆盖现有较新证据，也不得自动进入正式证据包。

### 16.3 资产与产品边界

- 正式导出只使用泰昌 `enterprise_fact` 且 `formal_bid_ready` 的资产。
- 新疆参考稿图片、辽宁/其他招标资料图片、河北豪乾图片在泰昌正式标书命中数为 0。
- 架空绝缘导线项目中 CPVC/MPP/N-HAP/UPVC 参数、工艺、报告和图片命中数为 0。
- 报告/证书证据包的实际插入页数与选定页序一致，失败页不得静默略过。

### 16.4 DOCX/PDF 交付

- 技术标、商务标分册封面口径为“投标文件 / 投标人：河北泰昌电力器材科技有限公司”。
- 目录层级、编号、页码、横向表格、附件分页正确，字段刷新成功。
- DOCX XML 不包含内部路径、API URL、检索分数、`taichang_*`、`production_capacity` 等内部字段。
- 对 300-600 页、300-500 媒体进行至少一次真实 DOCX -> 字段刷新 -> PDF 回归。
- 正式导出前不存在否决级未确认项；普通告警有明确人工豁免记录。

## 17. 风险分析

| 风险 | 级别 | 具体表现 | 应对策 |
| --- | --- | --- | --- |
| 把参考稿当成模板硬套 | P0 | 各省/批次目录差异被忽略 | 招标文件项目级规则最高优先 |
| 产品串用 | P0 | 电缆保护管资料出现在架空导线项目 | 产品族/物料/规格全链路门禁 |
| 表单被 AI 改写 | P0 | 表头、列、声明、签章位与招标原样不一致 | 原样表单结构化渲染/可编辑模板填充 |
| 无依据“无偏差” | P0 | 技术响应未经参数比对即承诺 | 参数及偏差结构化核对 + 人工确认 |
| 证据页不完整 | P0 | 只选中报告个别页或顺序错乱 | 原始文件级证据包和完整性门禁 |
| 时效资料过期 | P0 | 信用查询、证书、校准、财务年份不符本批要求 | 有效期/查询时间/年份集合检查 |
| 资料堆砌 | P1 | 为了模仿页数插入与评审无关证据 | 以第六章和评分项为章节收录依据 |
| 文件体积过大 | P1 | 上传超限或导出失败 | 图片分级压缩、可读性抽检、体积预算 |
| 敏感信息泄露 | P0 | 身份、社保、账户、审计、签章资料无授权输出 | 项目级授权、默认限制、导出审计 |
| 把结构对照做成通用平台 | P0 | 为多企业、任意模板和语义相似度扩张范围，延误泰昌交付 | 仅对两份固定泰昌骨架做标题/编号/表单的确定性差异对照 |
| 混淆结构角色与事实权限 | P0 | 因泰昌稿和新疆稿都可参考结构而错误合并事实权限 | 结构来源用 `origin_type`，事实权限继续用 `source_domain/reference_only` 独立控制 |
| 产品族相同即误判覆盖 | P0 | 因均为MPP而把φ250×22报告用于φ200×14项目 | 按固化ID、规格和关键参数逐项判断覆盖状态，`mismatch`阻断正式导出 |
| 非标准DOCX表格漏解析 | P0 | 技术规范封装DOCX缺失`w:tblGrid`导致常规解析器报错或漏表 | XML降级解析、显式告警和`needs_review`，不得静默跳过 |

## 18. 待业务评审/客户确认事项

1. 客户是否确认两份泰昌补充文件属于已正式提交/中标稿；未确认前统一称“泰昌标书人员提供并认可的历史编制稿/补充稿”。
2. 两份泰昌补充文件能否提供对应原始招标文件的第六章；如不能，需由泰昌标书人员逐条确认“招标条款映射/泰昌习惯补充/不确定”。
3. 泰昌补充文件是否已由投标人员审核为“企业标准事实包”，还是仅针对某个电缆保护管项目的临时编稿？
4. 《技术补充文件》中 CPVC/MPP/N-HAP/UPVC 报告、工艺和设备的当前有效性、适用型号及可公开范围。
5. 查询报告、审计报告、社保、身份证、银行资料是否允许系统托管并自动进入项目导出。
6. 未来主要交付物是 DOCX，还是实际上传的双层 PDF；若两者都要，验收以哪个为主。
7. 证据附件是默认全量收录，还是必须由投标人员在项目中勾选后收录；本稿建议高风险/敏感资料必须人工勾选。
8. 泰昌是否已通过SL2655要求的2026年度“电缆保护管MPP”联合资格预审；未确认前不得将SL2655作为可正式投标项目。
9. 泰昌能否提供MPP φ200×14且断裂伸长率≥200%的对应检验报告、技术保证值和产品事实；未提供前SL2655只能作为规则与缺口阻断样本。

## 19. 本轮最终建议

1. **不把需求简化为“把图片上限从 24 改成 400”**。核心是招标规则、表单、参数响应和文件级证据包，图片数量只是结果。
2. **目录骨架采用“当次招标规则 + 固定泰昌历史骨架差异对照”**。新疆稿只补充版式观感，不作为目录权威来源，也不提供泰昌事实。
3. **将两份泰昌补充文件作为 P0 数据治理与结构标注批次**。同时盘点章节来源和企业事实，但需先做原始资料回溯、内容级去重、证据包重建、产品适用性和时效性审核，不宜将 Word 内嵌图直接批量入库。
4. **有限采用 `template_docx` 混合路线**。只服务两份固定泰昌稿和招标原样表单，不建设任意模板上传、跨企业模板市场或通用语义相似度平台。
5. **保留当前文字型标书能力**。将其收敛到真正需要论述的章节，并让表单、参数、点对点响应、证据附件成为一等内容对象。
6. **先由泰昌投标人员确认章节来源、目录差异和否决规则，再启动代码实施**。建议先用 1 个与泰昌产品资料匹配的真实招标包做端到端样板，而不是一次性改全部生成链路。
7. **将SL2655提升为P0规则与资料缺口样本，而不是直接作为最终成稿正向样本**。只有资格预审状态和φ200×14证据覆盖确认后，才能进入正式投标导出验收。
