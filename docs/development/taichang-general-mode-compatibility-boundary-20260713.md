# 通用模式与泰昌历史标书复用模式兼容性边界

> 日期：2026-07-13
> 适用范围：河北泰昌电力器材科技有限公司 MVP 试点
> 状态：P0-07 边界已冻结
> 非目标：本文件不建设多企业、多行业模板平台，也不提前实现泰昌专版首页入口和完整编排规则。

## 一、结论

现有“上传招标文件生成标书”流程继续作为 `general` 通用模式，默认行为不变。泰昌历史标书复用能力使用独立的 `taichang_reuse` 模式，必须由后续专用入口显式传入；系统不得依据登录用户、租户或投标主体自动切换。

项目模式在创建时写入 `bid_projects.project_mode`，后续解读、章节生成、继续编辑和 DOCX 导出均从服务器项目记录读取模式。客户端提交的任务 metadata 不能覆盖服务器模式。

## 二、功能边界表

| 边界项 | `general` 通用模式 | `taichang_reuse` 泰昌复用模式 | 隔离要求 |
| --- | --- | --- | --- |
| 创建方式 | 现有上传入口默认创建 | 后续泰昌专版入口显式选择 | 未传模式一律为 `general` |
| 招标文件解析 | 复用现有 MinerU/OCR 链路 | 复用同一解析链路 | 解析结果按 `project_id` 隔离 |
| 项目动态骨架 | 保持现有通用规划逻辑 | 后续加载泰昌专版编排配置 | 泰昌规则不得覆盖通用默认配置 |
| 历史标书经验 | 不自动启用 | 只读取已审核、已版本化的泰昌历史参考骨架 | 不在日常任务中重新解析两份历史 Word |
| 企业事实资料 | 可使用已授权泰昌知识库、产品库和资信库 | 使用同一已审核事实基线 | 企业事实与招标要求、参考模板继续按 metadata 过滤 |
| 解读/生成任务 | metadata 固化 `general/general_v1` | metadata 固化 `taichang_reuse/taichang_reuse_v1` | 服务器模式覆盖客户端同名字段 |
| 继续编辑/重试 | 根据项目记录保持通用模式 | 根据项目记录保持泰昌模式 | 不从 URL 或页面临时状态推断模式 |
| 正式检查 | 复用现有检查能力 | 复用检查能力并由后续专版规则补充 | 本阶段不改变检查算法和默认规则 |
| DOCX 导出 | 复用现有正式导出链路 | 复用同一导出链路，任务保留模式上下文 | 模式不改变现有导出接口默认参数 |
| 功能关闭 | 始终可用 | `TAICHANG_REUSE_ENABLED=false` 时拒绝新建 | 关闭专版不得影响通用项目 |
| 异常回退 | 数据库迁移未就绪时允许按旧表创建并视为 `general` | 迁移未就绪时明确失败，禁止静默降级 | 防止泰昌项目丢失模式后串用通用规则 |

## 三、项目模式契约

数据库字段：

```text
bid_projects.project_mode
  general
  taichang_reuse
```

约束：

1. 旧项目及缺失模式的历史数据统一解释为 `general`。
2. 新建项目仅接受上述两个值，未知值返回 400。
3. 泰昌专版开关关闭时，新建 `taichang_reuse` 返回 503；新建 `general` 仍正常。
4. 项目元数据更新接口不允许修改 `project_mode`，因此客户端不能在项目创建后切换模式。
5. 最近任务、历史任务和项目解读响应均返回服务器规范化后的 `project_mode`。

任务 metadata 固定字段：

```json
{
  "project_mode": "general | taichang_reuse",
  "project_mode_contract_version": "project_mode_contract.v1",
  "orchestration_profile": "general_v1 | taichang_reuse_v1",
  "historical_bid_reuse_enabled": false
}
```

其中 `historical_bid_reuse_enabled` 仅在 `taichang_reuse` 为 `true`。

## 四、配置隔离与失败策略

- 通用模式不读取泰昌历史参考骨架、章节映射和专版规则。
- 泰昌模式只声明独立编排配置标识；具体历史骨架差异对照和生成规则在后续 P2 任务实现，不提前注入通用生成链路。
- 数据库迁移部署窗口内，如果 `project_mode` 列尚不存在，通用项目按旧结构继续创建；泰昌项目明确失败并提示先执行迁移。
- 生成、导出等任务的模式一律由项目记录生成，忽略客户端伪造或过期的模式字段。
- 页面刷新后，活动工作流保留模式；旧版浏览器本地任务没有模式字段时回退为 `general`。

## 五、与后续任务的关系

P0-07 只冻结和实现兼容边界，不提前扩大范围：

- 泰昌专版首页显式入口、文案和选择交互属于后续 D2/P2 页面任务。
- 泰昌历史参考骨架差异对照、章节编排和资料匹配属于后续 P2。
- P0-06 人工审批继续等待泰昌资料管理人员，不因 P0-07 完成而默认批准任何资产。
- 多企业、多行业、自定义历史模板中心仍不在本版范围。

## 六、验收结论

- 默认上传仍创建 `general` 项目。
- 只有显式提交 `taichang_reuse` 才创建泰昌专版项目。
- 旧项目、旧浏览器活动任务均回退 `general`。
- 解读、章节生成、导出任务持久化服务器权威模式。
- 客户端不能借 metadata 把通用项目切换成泰昌模式。
- 关闭泰昌专版后，通用项目创建和既有流程仍可运行。
- 本阶段未修改 RAG 资料、召回策略、正式资产 metadata、DOCX 排版或选图逻辑，不触发全量 RAG/DOCX 门禁。
