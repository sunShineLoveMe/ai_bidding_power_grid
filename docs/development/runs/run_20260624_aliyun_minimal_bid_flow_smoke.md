## 缺陷记录

| 编号 | 优先级 | 问题 | 影响 | 建议 |
| --- | --- | --- | --- | --- |
| ALI-BID-001 | P1 | HTTP 线上下载被 Chrome 拦截为弹窗和不安全下载 | 用户会误以为导出失败；首次下载需要手动允许弹窗并保留文件 | 线上启用 HTTPS；导出改为同页 `<a download>` 或后端返回 blob，避免弹窗下载 |
| ALI-BID-002 | P1 | 导出完成提示与投标信息确认页的正式缺口口径不一致 | 一个位置显示正式必填缺口 0，另一个位置显示 16，容易误导正式交付判断 | 统一使用同一 formal readiness 计算源；区分“正文明确占位缺口”和“客户变量确认缺口” |
| ALI-BID-003 | P0 | 投标信息确认页“项目业绩证明”候选误显示人员证书，如晁坤琳/陈仙瑞人员证书 | 业绩章节可能误用人员证书，属于企业事实映射错误 | 修正 evidence_type/category 到章节候选映射，项目业绩只允许合同、中标通知书、订单、验收单、发票等业绩证据 |
| ALI-BID-004 | P1 | 部分章节自动插图语义不准，例如投标函父章节插入绿色电力认证证书，技术响应/生产能力候选出现碳足迹报告页 | 草稿观感可接受度下降，正式导出可能出现不贴章节的图片 | 按章节类型增加图片白名单和负面规则；投标函、授权、保证金等法定格式章节默认不自动插图 |
| ALI-BID-005 | P2 | 编辑器预览中 `投标函及投标函附录` 出现重复标题，但 DOCX 抽取未发现同等重复 | UI 观感瑕疵，可能来自编辑器渲染标题和正文标题叠加 | 对 Tiptap 编辑器标题展示与导出 Markdown 做一致性检查 |

## 后续建议

1. 先修 `ALI-BID-003`，这是企业事实映射错误，优先级高于下载体验。
2. 再修 `ALI-BID-002`，统一正式缺口口径，否则客户无法判断“草稿可下载”和“正式可提交”的边界。
3. 同步修 `ALI-BID-001`，线上应尽快切 HTTPS；否则每次 DOCX 下载都会触发浏览器安全提示。
4. 完成后重跑同一项目的最小烟测，并补测至少一个技术章节正文生成和正式下载。
