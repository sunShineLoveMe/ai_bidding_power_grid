## 缺陷清单

### P0：线上当前项目不是客户可验收状态

线上唯一项目当前只有 `1/145` 个正文小节、1455 字，条款覆盖率 24%，高风险待覆盖 58。即使导出链路能跑通，客户看到的仍然是草稿级内容。

处理建议：把本地已验收的完整项目数据同步到测试环境，或在线上重新跑完整生成任务并完成正式检查闭环。

### P0：投标信息确认页 UI 与接口数据不一致

点击正式检查页“投标确认”后，页面显示“当前项目暂无投标确认报告”；但 `/prefill-report` 接口实际返回 35 个字段、26 个正式必填字段、16 个正式必填缺口。

影响：用户无法在 UI 中补齐正式导出必填缺口，正式检查阻断项无法闭环。

处理建议：修复 `BidPrefillPage` 对接口响应结构的判空和渲染逻辑，不能因 `confirmation_keys` 为空就判定无报告。

### P1：导出完成后被 Chrome 弹窗拦截

导出完成后前端使用 `window.open(download_url, '_blank')` 打开下载链接，测试环境被 Chrome 拦截。用户只能通过地址栏弹窗拦截提示找到链接。

影响：用户会误以为导出失败或没有下载结果。

处理建议：导出完成后在页面内展示明确的“下载 DOCX”按钮，并保留下载链接；自动打开可作为辅助，不应作为唯一入口。

### P1：下载前第一屏仍是条款覆盖率弹窗，正式门禁提示滞后

“标书下载”点击后先展示条款覆盖率弹窗，正式检查 8 个阻断项只在继续下载后通过 toast 提示。

影响：客户可能误解为只要忽略覆盖率就能正式下载。

处理建议：下载前弹窗应合并正式检查门禁结果，优先展示“仅允许草稿版导出 / 阻断项 8 / 必填缺口 16”，再展示覆盖率指标。

### P1：目录不是 Word TOC 字段

DOCX 中存在目录文本和页码，但未检测到 Word `TOC` 字段。当前页码已生成，后续人工编辑正文后目录无法像 Word 自动目录一样刷新。

处理建议：进入模板化 Word 模式或补齐 TOC 字段生成，至少在正式版导出中使用可刷新目录。

### P2：页眉口径与默认规则存在差异

当前页眉为“项目名称投标文件\t投标文件”；默认规则要求页眉为“河北泰昌电力器材科技有限公司投标文件”。如果采用客户最新通用格式，页眉可接受“左项目名称、右章节名称”，但当前右侧是固定“投标文件”，不是章节名称。

处理建议：明确模板优先级后统一页眉规则：客户 Word 模板 > 招标文件要求 > 项目默认模板。

### P2：正式检查表格存在易误读状态

正式检查表格中部分规则显示“阻断”级别但状态为“已通过”。技术上可理解为“阻断级规则已通过”，但客户容易误读为仍阻断。

处理建议：将列名改为“风险等级”和“检查结果”，或对已通过的阻断级规则弱化红色标签。

### P2：正式检查生成时间显示原始 UTC

页面显示类似 `2026-06-25T04:00:36...+00:00` 的原始时间格式。

处理建议：统一格式化为北京时间，例如 `2026-06-25 12:00`。

## 结论

阿里云测试环境本次发布已经生效：正式检查入口存在，正式检查 API 可用，DOCX 导出任务可完成，正式导出门禁会把当前项目降级为草稿版，字段刷新和图片插入链路通过。

但当前线上项目内容和投标确认 UI 不具备客户验收条件。下一轮优先处理 P0：同步/生成完整线上项目数据，并修复投标信息确认页无法展示接口报告的问题。
