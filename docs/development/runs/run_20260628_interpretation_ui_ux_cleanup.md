# 2026-06-28 招标项目解读页 UI 与业务文案治理

## 背景

客户反馈“招标项目 - 解读总览”页面纵向过长，且“查看依据”抽屉中出现 `同页 MinerU 分片`、英文优先级 `medium/high` 等用户难以理解的技术文案。

## 修复范围

- 解读总览：
  - 报告卡片增加高度上限和内部滚动，避免单个模块把页面撑得过长。
  - 文本列表默认展示前 4 条，支持“展开全部/收起”。
  - AI 卡片改为响应式多列布局，并限制长文本行数。
- 原文依据抽屉：
  - 增加用途说明，明确“这里展示本条结论对应的招标文件原文，便于人工复核”。
  - `直接依据` 改为 `本条依据摘录`。
  - `同页 MinerU 分片` 改为 `同页原文摘录`。
  - `AI 解读引用` 改为 `系统解读依据`。
- 解析详情：
  - `高级信息` 改为 `解析详情`。
  - `查看原文分片` 改为 `查看原文摘录`。
  - `MinerU 解析校验` 改为 `解析质量检查`。
  - 隐藏解析产物路径，不向业务用户展示内部文件路径。
  - `Markdown 字符`、`内容块` 等改为 `已识别文字量`、`原文摘录数` 等业务化文案。
- 中文化：
  - 优先级 `high/medium/low` 改为 `高/中/低`。
  - 风险等级 `high/medium/low` 改为 `高风险/中风险/低风险`。
  - 项目状态 `uploaded` 改为 `已上传`。
  - 项目概况不再展示内部项目 ID。
  - 原始解析摘要中的 `MinerU/Markdown/结构块` 统一转为业务摘要。
