## 关键发现

1. 两份文件是正式成稿分册，不是空白模板：
   - 技术标 DOCX 约 `96MB`，PDF `512` 页，`82` 张表，`408` 个媒体资源。
   - 商务标 DOCX 约 `31MB`，PDF `177` 页，`3` 张 Word 表，`168` 个媒体资源。
   - 大量内容是扫描件、查询报告、检验报告、审计报告、证书等证据页。

2. 版式基线稳定且值得采纳：
   - A4：`11906 x 16838` twips。
   - 页边距：上/下约 `2.54cm`，左/右约 `3.17cm`。
   - 页眉基本为空，不放公司 Logo。
   - 页脚只保留页码，整体黑白、克制。
   - 目录为 Word TOC 字段：`TOC \o "1-4" \h \u`，配合 `HYPERLINK + PAGEREF`。

3. 样式特征：
   - Normal 默认接近 `10.5pt`。
   - 一级标题约 `22pt`，二级标题约 `16pt` 黑体加粗。
   - 正文/表格主体大量使用宋体 `10.5pt` 或 `12pt`。
   - 目录点引导线密，目录字体不夸张，页码右对齐。

4. 结构特征比字体更重要：
   - 技术标主线：技术偏差表、技术特性参数表、货物组件材料配置表、评审要素补充文件、技术文件、检测检验报告、其他。
   - 商务标主线：商务偏差表、补充文件、查询报告/截图、财务状况、评审要素补充材料、授权委托书。
   - 正式稿不是长篇散文，而是“表单 + 参数响应 + 证据附件页”的分册结构。

## 与当前系统导出的对比

当前系统 `formal_bid_standard` 已具备的基础能力：

- A4、黑白文本、页眉无 Logo、目录点引导线、页脚页码字段刷新。
- 正文小四 `12pt`、1.5 倍行距。
- 图片统一框尺寸，当前真实导出插图 `24/24` 成功。

主要差距：

- 当前导出仍偏“通用全文标书”，目录和章节来自系统章节树，业务分册感不如正式参考稿。
- 技术标缺少独立的“技术特性参数表 / 点对点应答 / 货物组件材料配置表”模板化生成骨架。
- 商务标缺少独立的“查询报告、财务状况、评审要素补充材料、授权委托书”模板化附件组织规则。
- 当前自动插图是按知识库资产插入，参考稿更像“附件整页证据册”，需要按证据类型整页排布。

## 建议

建议把这两份正式文件升级为 `formal_bid_xinjiang_sgcc_reference` 参考模板族，而不是直接用作可编辑套打模板：

1. 抽取并固化两套分册模板：
   - `technical_bid_standard`：技术偏差表、技术特性参数表、点对点应答、组件材料配置、技术评审补充、检测报告、其他。
   - `business_bid_standard`：商务偏差表、人员关系说明、查询报告、财务状况、评审补充、授权委托、银行资信/社保/承诺等。

2. 保留当前 `formal_bid_standard` 作为通用兜底，但导出时按技术标/商务标分别选择模板骨架。

3. 版式可采纳：
   - 页眉继续不放 Logo。
   - 页边距建议评估切到左右 `3.17cm`，更接近参考稿。
   - 目录可以支持 1-4 级，但必须有“目录层级白名单”：正式技术/商务表单和附件证据才进深层目录，避免重复资产标题污染目录。
   - 表格可适当改为更紧凑的 `10.5pt`/宋体，用于参数表和证据表；正文说明继续保留小四/1.5 倍或按招标文件要求覆盖。

4. 内容生成要从“章节正文”升级到“分册对象模型”：
   - 先生成技术/商务分册目录对象；
   - 再生成表单对象、参数表对象、附件证据对象；
   - 最后由 DOCX 导出器按对象类型选择模板渲染。

5. 禁止直接混用参考稿事实：
   - 参考稿企业、招标编号、产品、检测报告、证书、审计报告均不得进入泰昌正式事实。
   - 只能引用其版式、目录组织和文件结构。

## 结论

可用，且参考价值高。最值得采用的不是它的某个字体，而是正式中标稿的分册组织方式：技术标和商务标必须分开建模、分开渲染，正文类内容减少，表单/参数/附件证据页成为主结构。建议下一步做“新疆中标参考模板抽取与模板族落地”任务，不建议继续只在当前通用 DOCX 导出器上微调字体。
