## 1. 需要纠正的原判断

在 2026-07-11 对上述两份文档的评审中，曾给出以下判断：

> "招标文件很少会精确到'5.1.3 质量管控体系'这种三级标题的措辞，大部分招标文件只会说'评审要素相关补充材料'，具体怎么拆成小节，实际上大概率会退回到抄新疆的默认骨架。"

**该判断已被证伪。**

核实证据：直接读取 `assets/template_words/.../招标文件其他章节-SL265A.docx`，其在该样本第六章“投标文件格式”的“三、技术文件”部分列出的条目（技术偏差表、专项投标文件、技术特性参数表、货物组件材料配置表、生产装备、调试试验场所与试验检测设备、制造工艺、认证证书、主要技术人员及证书、检测检验报告等）与调研稿第 7.2 节“建议项目级技术标骨架”逐条对应，标题措辞基本一致。也就是说，这份招标文件对技术标目录的规定已经精细到具体条目和格式名称层级，不是含糊的大类描述；但“第六章”仅是 SL265A 的样本位置，不是其他项目的固定定位规则。

同时，经与泰昌标书人员当面确认得到关键信息：

> 招标文件"投标文件格式"部分的规定，与泰昌历史标书的章节目录、排版基本一致；每次具体投标会做细微调整，因为部分内容确实逐项目而异。

这说明泰昌人员早已发现并依赖了这个规律——国网同类招标中承担“投标文件格式、组成和编制要求”的章节或附件具有一定跨项目稳定性，泰昌的实际工作方式一直是“拿历史稿子改一改”，不是每次从零推导目录。其章节编号、所在文件和适用条件仍可能变化，系统必须每次重新定位。

## 2. 修正后的结论

### 2.1 骨架稳定性的来源需要重新归因

不应把"新疆稿子的目录结构"和"泰昌标书人员提供的历史编制稿目录"简单理解为两份互相独立的风格偏好，也不应认为系统的默认骨架是在"抄某家公司的审美"。二者在结构层都属于历史落地样本，但事实权限必须严格区分：新疆稿始终仅供参考，泰昌稿中的事实也必须回溯原始资料并审核后才能使用。

准确的归因是：

> 骨架的稳定性主要来自国网招标制度本身的惯性（同类物资、同类批次中承担投标文件格式、组成和编制要求的内容高度复用）。新疆稿和泰昌历史编制稿都是制度性条款的历史落地样本；当次招标文件全套内容、附件及澄清补遗仍是权威来源，系统必须全文语义定位实际结构来源，不得预设第五章、第六章或主文件。

这也意味着此前"招标文件权威 > 参考模板"的五级优先级设计，方向没有错，但描述方式不准确：不是"权威规则压过参考风格"，而是"稳定骨架 + 逐项目变动量"两层叠加，需要分开建模。

### 2.2 "细微调整"需要拆成三类分别处理

泰昌人员所说的"每次投标做细微调整"，实际包含三类性质不同的变动，之前两份文档没有做区分：

| 变动类型 | 特征 | 处理原则 |
| --- | --- | --- |
| 招标方规定层面的变动 | 例如本批次"业绩文件不适用，以资格预审结果为准"、"免收投标保证金"；下一批次可能规定不同 | 必须严格来自当次招标原文重新判定，不能沿用历史项目结论，即使历史骨架高度相似也不能默认沿用条件章节的取舍 |
| 内容填充层面的变动 | 产品规格、参数、证书编号、金额、日期、人员等纯事实内容 | 属于证据/参数层的替换，与章节结构无关，可按已有的结构化参数、证据包机制处理 |
| 表单、版式与提交层面的变动 | 原样表格、签章位、分页、文件类别、上传端口 | 招标原样优先；固定表单和稳定版式块可有限复用，不能由 AI 改写 |

原调研稿把这些变动都放进“目录权威合并”一个环节里笼统处理，容易让执行时分不清“哪些差异必须重新审，哪些可以复用历史经验或表单”。建议先对当次招标文件包做全文语义定位并生成项目动态骨架，再与历史参考骨架做确定性差异对照和条件章节判定，最后进行事实填充与表单渲染。

### 2.3 泰昌"理想标书"的定位需要重新调整

两份原文档（尤其是 V1 清单 P0-03"两份 Word 只读拆解"）把泰昌提供的《技术补充文件》《商务补充文件》定位为"泰昌事实与证据编排稿"，重点关注其中的事实、参数、证据候选。

修正后的定位：这两份文件同时承载了两层信息，且此前的方案设计低估了结构层价值——

1. **章节骨架层**：反映当次（或某次）招标中实际承担投标文件格式、组成和编制要求的章节/附件，在泰昌实际编制工作中如何被拆解、落地。这一层比新疆稿更贴近泰昌工作习惯；在客户确认前，不把它表述为正式提交稿或中标稿。
2. **企业事实层**：产品参数、证书、业绩等，这是原方案已经关注的部分。

如果这两份稿子对应的原始招标文件包可获取，应该先全文语义定位实际结构来源，再把两者对照，明确标注“这份稿子里哪些章节/条目是当次招标条款的直接映射，哪些是泰昌自己额外补充的习惯性章节”。如果原始招标文件不可得，至少应让泰昌标书人员逐条确认：“这个章节即使换一次招标批次也基本不会变”还是“这是这次特有的”。

这个标注目前在 V1 清单的候选资产字段设计中不存在，建议增加 `origin_type`，至少区分 `tender_mandated / tender_conditional / tender_scoring_derived / taichang_habitual_addition / reference_layout_only / uncertain`。

### 2.4 对 `template_docx`（P0-8）路线价值的重新评估

此前评审在讨论"两条技术路线"（规则生成 vs 模板变量替换）时，倾向于认为规则生成路线更通用、模板替换路线成本更高且适用面窄。这个权衡需要重新考虑：

既然同类项目骨架具有一定稳定性、逐项目变动主要集中在事实填充和条件章节取舍，固定表单及稳定版式块采用历史 DOCX 定位填充的思路贴合泰昌人员工作习惯，其价值被此前评审低估了；但这不等于本期应建设任意 DOCX 自动模板化能力。

但无论走“规则重新生成”还是有限的固定表单/版式块定位填充，都绕不开同一个前置能力：**先从当次招标文件包生成项目动态骨架，再与两份泰昌历史参考骨架逐项对照，明确新增、删除、名称、顺序和条件差异**。

建议：V1 先把“当次项目动态骨架 + 历史参考骨架确定性对照 + 差异清单”作为共享前置步骤，不建设跨企业、跨行业的语义相似度平台，也不在两条路线中重复实现。

## 4. 结论

原方向判断（招标文件优先、新疆/泰昌稿仅作参考）基本正确，但对"参考模板占比"和"骨架来源"的具体描述有事实误差，已通过阅读原始招标文件和泰昌人员访谈纠正。核心结论调整为：

1. 目录骨架的稳定性主要来自国网招标制度本身，不是某家公司的版式偏好；新疆稿、泰昌历史稿的作用是历史落地样本，用于历史参考骨架差异提示，而非骨架权威来源。权威来源仍是当次招标文件全套内容、附件及澄清补遗；实际结构来源必须逐项目语义定位，章节号不能写死。
2. "逐项目细微调整"应拆成招标规定变动、事实内容填充变动、表单版式与提交变动三类分别处理。
3. 泰昌两份补充文件的骨架层价值应被重新重视，需要标注每条内容的来源属性（招标条款映射 / 泰昌习惯补充），而不是整份当作事实证据源笼统处理。
4. `template_docx` 的价值主要体现在招标原样表单和已确认稳定版式块；V1 与规则生成路线共享“项目动态骨架与两份泰昌历史参考骨架确定性对照”前置步骤，不扩展为任意模板上传或通用相似度平台。

建议后续评审在锁定技术路线前，先与泰昌标书人员确认现有两份补充文件是否能提供对应的原始招标文件包，用于定位实际结构来源并比对；如不能完整比对，则至少需要人工逐条标注骨架来源属性，再进入 P0 资产盘点。本期不要求继续收集或支持其他企业、其他历史项目模板。

## 5. SL2655 新疆MPP招标包二次验证（2026-07-13）

新增完整招标包 `包1_完整招标文件_92475576192439826` 后，原评审结论得到进一步验证：该 SL2655 样本实际位于第六章的内容提供价格、商务、技术文件骨架和原样表单，但资格预审、保证金、业绩、生产装备、检测设备、制造工艺、认证证书、人员和检测报告等内容会按项目条件被标为继承、允许补充或不适用。因此，历史标书复用必须同时维护“章节来源”和“当前项目状态”，不能只复制历史目录；其他项目仍需重新定位实际来源。

该包定位为 `source_domain=tender_requirement` 的泰昌物资类规则样本，不是泰昌历史投标成稿，也不是泰昌企业事实。其MPP要求为内径200mm、壁厚14.0mm、断裂伸长率≥200%，而泰昌现有结构化检验报告为内径250mm、壁厚22mm、断裂伸长率实测176%，只能判定为产品族相关但规格/关键参数不覆盖。SL2655因此进入P0“规则正向与资料缺口阻断”样本；在资格预审状态和φ200×14证据补齐前，不作为最终成稿正向样本。

本次验证不改变泰昌单企业试点边界，不扩展任意模板上传、跨企业模板推荐或通用语义相似度能力。

进一步读取《技术补充文件》的正文、10 个表格和媒体结构后，确认该文件既有泰昌一手资料价值，也存在项目抬头、物料和产品内容混杂。尤其是 `SL265 / 1kV架空绝缘导线-新疆`、PVC 复合材料管规范与 MPP/CPVC/N-HAP/UPVC 企业能力同时出现，因此不能按“整份 Word = 泰昌已核验产品事实”处理。

对原需求和任务清单的影响如下：

1. 原有“只读拆解—四层去重—人工审核—增量入库”路线正确，继续保持 P0，不新增独立平台或新产品范围。
2. 技术参数需要增加证据等级。检验报告实测值、投标人保证值、招标要求值、产品清单规格和笼统响应必须分开；“完全响应”不能替代具体保证值。
3. MPP 报告 `2024100312005501712` 和 CPVC 报告 `2024100312005501713` 已存在于系统，不得重复入库，只补历史标书来源映射。
4. N-HAP 报告 `2024400312005505333` 和 UPVC 报告 `2025200312005503479` 当前只作为待补原始证据线索；未取得完整报告前不得生成正式参数。
5. 历史产品清单中的 φ50、φ100、φ150、φ175、φ200 等规格只能登记为候选产品规格，不能推断泰昌已有全部规格的检验报告。
6. 六类试验设备与现有设备台账、现场图片和 2026 年校准资料重复，应归并来源并采用较新证据；不得回退为历史 Word 中的旧日期。
7. 职业健康安全管理体系证书 `626023S10219R0` 已于 2026-06-18 到期，应进入过期阻断清单，等待续证。
8. 人员电话、地址和证件信息继续按 `restricted` 管理，不进入普通知识问答和自动导出。

因此，本次审计不是新增功能方向，而是把既有 P0/P1 任务补成开发可验证的事实样本。开发仍以泰昌单企业、国家电网物资供货类技术标/商务标为边界。
