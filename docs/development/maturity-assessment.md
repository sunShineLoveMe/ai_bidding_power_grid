**定位：中等成熟度的"测试版底座 + 电网行业适配"系统，核心链路真实贯通、可演示、可单企业试用。不是 PPT 工程，但距"生产级稳定交付"仍有明确差距。**

## 4. 核心业务模块实现程度

### 4.1 招标文件解析

**成熟度：⭐⭐⭐⭐ 高**

- 集成 MinerU API 处理扫描版 PDF 和复杂表格（`backend/parsing/mineru_client.py`）
- 原生 PyPDF2 / Mammoth 处理常规 PDF 和 DOCX（`backend/parsing/document_parser.py`）
- 解析状态持久化到 `bid_parse_tasks` 表，支持失败重试、断点续传和状态展示
- MinerU zip 下载支持 `.part` 断点续传 + HTTP Range

### 4.2 结构化解读

**成熟度：⭐⭐⭐⭐ 高**

- 多阶 LLM 解读剥离"项目概况 / 资格要求 / 商务要求 / 技术要求 / 评分项 / 风险项"（`backend/ai/interpreter.py`）
- 解读结果落库 `bid_analysis` / `bid_requirements` / `bid_scoring_items` / `bid_risks`

### 4.3 分册大纲生成

**成熟度：⭐⭐⭐⭐ 高**

- 五册模型：技术标 / 商务标 / 资格文件 / 报价文件 / 附件材料（`backend/core/bid_volumes.py`）
- 分册注入不同写作策略、资料召回侧重点和图片策略
- AI Prompt 输出分册 + 规则 fallback 兜底，兼容扁平 chapters
- 分册大纲落库加固：串行批量替换，避免 Supabase 网络抖动导致写入失败

### 4.4 章节写作计划

**成熟度：⭐⭐⭐⭐⭐ 极高**

- `bid_writing_plan.py` 是系统核心能力，根据章节类型/重要性/评分项/风险项/材料需求动态计算：
  - 目标字数、建议页数
  - 是否需要表格/图片/资质/案例支撑
  - `single_pass` 或 `multi_pass` 生成模式
- 支持全文篇幅设置覆盖和用户自定义字数分配

### 4.5 正文生成

**成熟度：⭐⭐⭐⭐ 高**

- 多轮续写（`multi_pass`）规避长文本 Token 上限截断（`backend/ai/section_writer.py`，541 行）
- SSE 流式输出，实时渲染正文
- 失败保稿保护：生成失败时不清空用户编辑稿或上一版成功正文
- 分册正文策略：技术标/商务标/资格文件分别注入不同写作约束和资料召回
- ⚠️ 章节正文生成仍在 `sections/stream` SSE 请求内实时执行，未迁入 Celery 任务队列

### 4.6 合规检查

**成熟度：⭐⭐⭐ 中**

- 规则版（`backend/ai/compliance_checker.py`）：
  - 分词命中 + 关键词匹配覆盖度校验
  - 输出已覆盖 / 待补强 / 未覆盖 / 高风险未响应
  - 分册摘要和明细列表
- 语义复核 MVP（`backend/ai/semantic_compliance.py`）：
  - LLM 复核高风险项、评分项、未覆盖项
  - 输出证据摘录、置信度、补强建议
  - LLM 失败时规则兜底
- ⚠️ 覆盖率基于分词命中计算，不等同于最终投标合规结论，交付时必须强调人工复核

### 4.7 RAG 知识库

**成熟度：⭐⭐⭐⭐ 高**

- 统一使用 PostgreSQL + pgvector（HNSW 索引），ChromaDB 已移除
- Embedding 后端**可切换**：默认百炼 `text-embedding-v4`（1024 维），当前开发环境已切到本地 Ollama `qwen3-embedding:0.6b`（1024 维）；切模型/维度需全量重嵌
- 父子双层分块（`backend/rag/chunking.py`）：按 doc_role 路由切分，子块参与向量召回、父块保留写作上下文，子块经 `parent_index` 回溯父块
- **场景化召回已进生产主链路**：`search_knowledge_base()` 支持 `scenario`（qa/writing/compliance）路由，调用 `match_knowledge_chunks_filtered` 做 metadata + `project_id` 定向过滤；写作场景 `_attach_parent_context` 回溯父块；doc_role 命中不足时自动放宽 fallback；最后经 DashScope Rerank（`qwen3-rerank`，fail-open）重排
- 召回基线（Ollama `qwen3-embedding:0.6b`，30 条 Base 测试集）：Recall@5 86.7%、来源类别准确率 100%、跨 doc_role 串扰 0%（过滤关闭时串扰 30%，见 `docs/rag/evaluation-records.md`）
- RAG 回答支持 SSE 流式输出 + 追问建议 + 图片资产内联展示
- ⚠️ 缺少混合检索（BM25 关键词 + 向量），电网专有名词/设备型号/标准号可能漏召回
- ⚠️ 15 份关键 PDF 国标/规范（GB 50150、GB 50168、DL/T 5729 等）未入库，技术标知识库不完整
- ⚠️ 部分国网规章种子文件（来源为 gov.cn 占位页）抓取到的是网站导航/首页内容而非规章正文，需重采

### 4.8 DOCX 导出

**成熟度：⭐⭐⭐⭐ 高**

- 任务化后台生成（Celery），前端轮询进度并自动下载（`backend/export/md_to_word.py`）
- 图文并茂：根据章节上下文自动从知识库匹配并插入图片
- 图片失败降级：下载失败/超大/格式异常时跳过，不中断导出
- LibreOffice headless 自动刷新目录页码和总页数
- 国标化基础：宋体/仿宋、行距、页边距、页眉页脚
- ⚠️ 封面字段、国网目录编号预设、表格样式和客户固定模板适配待增强

## 7. 给技术团队的建议

### 7.1 短期（云账号与完整客户资料到位前，1-2 周）

1. **优先补 P0-9 标准库缺口** — 先做 GB/DL 标准 PDF 样板入库；有 MinerU token 时批量解析，没有 token 时先做 3-5 份关键标准样板。
