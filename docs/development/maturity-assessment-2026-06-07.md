## 1. 总体结论

**定位：中等偏上成熟度的"测试版底座 + 电网/泰昌单企业适配"系统。核心主链路真实贯通、可演示、可单企业试用，且已经在本地用真实辽宁招标样本 + 泰昌企业资料跑通入库与召回评测。不是 PPT 工程。**

距离"生产级稳定交付"仍有明确差距，主要集中在：**阿里云真实资源未联调、图片资产向量缺失导致图文语义召回不可靠、技术标关键国标 PDF 未入库、单章正文仍走 SSE 实时生成、无浏览器级 E2E**。

主链路（上传 → MinerU 解析 → 结构化解读 → 分册大纲 → 章节正文 → 合规检查 → DOCX 导出）每一环都有真实实现。DOCX、解析、知识库入库、大纲精炼和批量章节生成已具备 Celery 后台任务链路；单章 `/sections/stream` 仍是请求内 SSE + 后台线程实时生成。

## 5. 当前最大风险（按严重程度排序）

### 风险 1（新发现，高）：图片资产向量全部缺失，图文语义召回不可靠

- **证据**：直连数据库统计，`knowledge_assets` 共 300 条，其中 `embedding is not null` 的为 **0 条**；其中 299 条为 `customer_pdf_full_page_render`（泰昌 PDF 整页渲染）、1 条 `customer_original_image`。
- **根因**：这些资产通过 `scripts/batch_import_mock_assets.py`（支持 `--no-embedding`）批量导入，未生成向量。而召回 RPC `match_knowledge_assets` 带 `where ka.embedding is not null` 硬过滤。
- **影响**：向量语义召回对这批泰昌资产实际命中为 0；当前业务检索依赖关键词/规则 fallback，能命中“营业执照、生产线、检验报告”等标题明确的资产，但泛化查询、语义相近查询和自动配图排序质量不稳定。经 API 上传（`assets.py` 的 `_maybe_attach_asset_embedding`）的资产会正常带向量，问题集中在批量导入的存量资产。
- **建议**：写一个 backfill 脚本，对 `searchable_text` 非空且 `embedding` 为空的资产批量补向量，再重跑资产召回验证和真实 DOCX 图文导出观感复验。这是图文能力从“规则可演示”升级到“语义可靠”的前置项。

### 风险 2（高）：阿里云真实资源未联调

- 本地 `/api/ready` 全绿不等于云上 RDS pgvector、OSS Endpoint、云 Redis、网络/安全组可用。阻塞所有云上验收（P0-1/5/6/7/11）。

### 风险 3（高）：技术标关键国标全文不完整

- `power_grid_standards_specs` 仅 7 份文档（含 1 份目录占位）。历史报告记录的 GB 50150/50168/50169、DL/T 5729 等电气安装验收标准 PDF 仍未完整入库。技术标正文与合规响应缺少标准全文支撑，易生成泛化内容。

### 风险 4（中）：单章 SSE 正文生成仍受请求链路影响

- 批量章节生成已具备 Celery 调度链路；但单章 `sections/stream` 仍在请求内以 SSE + 后台线程实时执行，受连接超时/浏览器中断影响。前端已做轮询回填与失败保稿缓解，但单章链路仍需继续收敛或明确产品边界。

### 风险 5（中）：合规检查是辅助判断

- 覆盖率基于分词命中，语义复核 LLM 失败即退规则。"条款响应率 100%" 不能等同最终投标合规，交付必须强调人工复核。

### 风险 6（中）：集成/E2E 测试不足

- 138 个后端 unittest + 1 条 HTTP 冒烟脚本 + RAG 召回评测；**无浏览器 E2E、无真实全链路自动化回归**，回归依赖人工。

### 风险 7（低-中）：RAG 召回 compliance 场景偏弱 + 少量污染数据

- 实测 compliance 场景 Recall@5 仅 50%（样本 4 条，基数小）；未命中用例 T17/T18 召回到空内容（`top1_role=None`），印证历史记录的"gov.cn 占位页/导航页污染"问题仍未清。

## 7. 给不同角色的建议

**给管理层**：系统是真东西，本地真实链路能跑通、能演示、能做泰昌单企业试点。但"能演示"到"能交付生产"还差几件硬事：图片资产向量缺失（图文语义召回和自动配图排序不可靠）、阿里云零联调、技术标国标不全、单章 SSE 链路仍需收敛、无浏览器 E2E。其中图片资产向量是本次新发现、且修复成本低，应优先处理。

**给开发团队**：优先级建议——(1) 资产 embedding backfill；(2) 国标 PDF 入库；(3) 单章 SSE 生成链路收敛；(4) 污染数据清洗 + compliance 测试集扩充；(5) Alembic 增量能力与大文件拆分。云账号到位后再做全栈云联调与 RDS 连接池容量复核。

**给产品团队**：图文并茂是泰昌标书的核心卖点之一，资产向量缺失会影响语义查询、自动配图排序和解释可信度，需推动尽快 backfill 后做真实导出观感复验。技术标国标入库直接决定技术响应质量。
