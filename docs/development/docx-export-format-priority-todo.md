# DOCX 正式导出格式评审整改优先级清单

更新日期：2026-06-29

关联评审稿：[标书 DOCX 导出格式评审稿（对照客户新疆中标参考稿）](docx-export-vs-customer-reference-review.md)

## 1. 定位与边界

本清单用于跟踪 DOCX 正式投标文件导出格式整改。新疆两份 10kV 架空绝缘导线中标参考稿只是客户提供的高质量参考样本，用于帮助判断“正式投标文件应该像什么”，不代表系统必须完全套用新疆稿，也不代表所有项目都采用新疆稿的页眉页脚、编号、字体和附件体量。

执行原则：

- 招标文件或中标参考稿可作为版式、目录组织、分册结构、格式表单和交付观感参考。
- 参考稿中的企业事实、产品参数、证书、检验报告、业绩、图片和附件内容不得复用为泰昌事实。
- 若招标文件明确格式要求，优先级高于参考稿样式。
- 当前 MVP 默认仍是单企业私有化、泰昌投标主体、国家电网配网物资类投标辅助。
- 每完成一项整改，必须同步更新本文件任务状态，并在 `docs/development/runs/` 写入真实导出或解析验证记录。

- `最近更新`

## 6. 建议执行顺序

1. 先完成 `P0-1`、`P0-2`、`P0-7`：先把适用范围、证据和交付边界钉住。
2. 再完成 `P0-3` 到 `P0-6`：这些是最明显、风险较低、收益较高的版式和字体修复。其中 `P0-3`、`P0-4`、`P0-5` 都集中在 `set_document_format` 页眉页脚/首页页码策略，建议同一批代码修改、一次真实导出统一验收，避免分三次回归互相覆盖。
3. 接着完成 `P1-1`、`P1-2`：封面观感收益高，改动范围相对可控。
4. `P1-4` 按高风险生成层关联任务处理：先完成设计评审和 `report_only` 元数据落地，不直接改 `chapter_planner.py`；后续如需接入生成层，单独设子任务和真实项目回归门禁。
5. `P2` 单独立项，不混入本轮格式修复，避免范围失控。

## 7. 验证门禁

任一 P0/P1 任务完成后，至少满足：

- 代码变更有对应单元测试或脚本验证。
- 至少跑一次真实导出链路：`build_project_bid_markdown -> convert_md_to_word -> refresh_docx_fields_with_soffice`。
- 对 DOCX XML 做专项检查，例如页眉、页脚、字体、字段、目录、图片数量、内部路径和占位符。
- 涉及观感的任务，应保存截图或 PDF 抽样页到 `docs/development/runs/` 或同目录子文件夹。
- 更新本文件对应任务状态。
- 更新 `docs/development/docx-bid-export-quality-todo.md` 的关键结论或历史记录。
