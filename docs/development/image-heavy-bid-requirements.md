# 图片型标书功能需求方案

状态：需求方案草案  
适用项目：AI 标书系统 - 国家电网投标智能工作台  
默认试点企业：河北泰昌电力器材科技有限公司  
编写日期：2026-07-05  

## 1. 需求背景

客户在使用辽宁招标文件测试系统后，认可系统可以较好完成技术标和商务标的大量正文输出。但客户对比新疆提供的一份标书样式后提出疑问：该标书正文中大部分内容是图片、扫描件、报告页或证书页，而不是大段可编辑文字。

因此，系统需要在不破坏当前“正式生成大量文字标书”能力的前提下，补充“图片型标书”的资料管理、章节编排和 DOCX 导出能力。

当前必须实事求是地说明：

- 系统已有图片资产入库、编辑器插图、DOCX 插图导出的基础能力。
- 当前默认能力更偏“正文型标书 + 少量关键配图”，不是专门面向“大量图片连续编排”的成熟功能。
- 若客户后续确实要求图片型标书，需要新增 UI、章节级图片编排、导出模式、图片质量门禁和导出审计。

## 2. 业务目标

1. 支持客户将大量泰昌正式图片资料整理成项目图片包。
2. 支持按技术标、商务标、资格文件、附件材料组织图片。
3. 支持同一项目在不同导出模式之间切换，避免和当前文字型标书冲突。
4. 支持图片型标书仍保持正式投标文件观感，包括封面、目录、页眉页脚、页码、题注、A4 版式。
5. 严格保证正式标书中只使用泰昌企业事实资产，不混用辽宁招标资料或河北豪乾参考稿图片。
6. 为后续客户演示、真实试点和批量导出建立可扩展基础。

## 3. 用户角色

| 角色 | 主要诉求 |
|---|---|
| 标书编制人员 | 快速把客户整理的大量图片编排进技术标、商务标，并导出正式 DOCX |
| 资料管理员 | 上传、分类、清洗、复核图片资产，确保图片可追溯、可用于正式标书 |
| 项目负责人 | 审核图片型标书是否符合招标文件、客户口径和正式交付质量 |
| 系统管理员 | 管控图片资产来源、权限、质量状态和导出审计记录 |

## 4. 当前能力与差距

### 4.1 当前已有能力

- 企业资信库、企业产品库已支持上传图片、PDF、证书、产品资料等资产。
- 图片资产可带 metadata，例如来源文件、页码、企业、资料域、证据类型、目标库等。
- 标书编辑器已有图片插入基础能力。
- DOCX 导出链路已有 `withImages=true` 相关能力。
- 系统已有正式导出基础格式：封面、目录、页眉页脚、页码、正文样式等。

### 4.2 当前不足

- 当前导出更偏向“文字正文为主，少量配图”，不适合一次性插入数百张图片。
- 缺少项目级“图片包”概念，无法清晰表达哪些图片属于本项目、哪个分册、哪个章节。
- 缺少章节级图片顺序编排能力。
- 缺少图片型标书专用导出模式，例如连续图片页、整页证据页、图片题注策略。
- 缺少导出前图片质量门禁，例如清晰度、来源合法性、是否可用于正式标书。
- 缺少“文字型、图文型、图片型”之间的明确模式隔离。

## 5. 核心设计原则

1. 不推翻现有文字型标书能力，只增加新的导出策略。
2. 底层内容统一管理，导出时按模式决定版式。
3. 图片必须可追溯，正式导出不得使用模型编造路径或来源不明图片。
4. 图片、正文、表格、附件证据页应作为不同内容块管理。
5. UI 保持当前后台工作台风格，不做营销式页面。
6. MVP 优先解决真实客户试点，不做过度复杂的版式设计器。

## 6. 导出模式设计

系统建议保留四类模式，其中“标准正文型”为当前默认能力，其余三类为图片型标书相关扩展。

### 6.1 标准正文型

定位：当前系统默认能力。

特点：

- AI 生成正文、表格、承诺内容为主。
- 系统自动插入少量关键图片。
- 适合常规技术标和商务标。
- 对现有业务影响最小。

适合场景：

- 客户希望输出完整可编辑文字标书。
- 招标文件未要求大量扫描件或图片正文。
- 后续需要频繁修改文字内容。

### 6.2 图文增强型

定位：当前正文型标书的增强版本。

特点：

- 正文仍然是主线。
- 在关键章节插入更多泰昌真实图片资产。
- 图片用于增强证据感和可信度。
- 适合“文字 + 产品图 + 检测图 + 证书图”的正式标书。

典型章节：

- 生产制造能力。
- 试验检测能力。
- 产品质量保证。
- 绿色低碳资料。
- 项目业绩证明。
- 企业资质能力。

适合场景：

- 客户认可当前正文输出，但希望更图文并茂。
- 图片资料较多，但不希望正文主体全部变成图片。
- 需要兼顾可读性、可编辑性和正式观感。

### 6.3 图片附件型

定位：客户当前关注的“正文大部分是图片”的标书形态。

特点：

- 每个章节保留少量文字说明。
- 正文主体由大量图片页、整页证书、整页报告、扫描件组成。
- 图片可按章节连续编排。
- 图片下方显示正式中文题注。
- 目录、页码、页眉页脚仍由系统统一生成。

典型内容：

- 生产线照片。
- 检测设备照片。
- 产品实物图片。
- 检验报告整页图片。
- 营业执照扫描件。
- 资质证书扫描件。
- 中标通知书、合同、业绩证明扫描件。
- 财务审计报告或银行资信证明扫描页。

适合场景：

- 客户明确要求参考新疆标书样式，大量页面为图片。
- 客户已经整理好大量高清图片或 PDF 扫描件。
- 资料本身以证书、报告、合同、扫描件为主。

主要风险：

- 文件体积会明显增大。
- 后期修改不如文字方便。
- 图片清晰度和排序依赖人工复核。
- 若缺少质量门禁，容易把不合规图片放进正式文件。

### 6.4 混合型

定位：真实投标场景中最灵活、最长期可用的模式。

特点：

- 不按整个标书统一一种样式，而是按分册、章节设置输出策略。
- 技术标、商务标、资格文件可以分别控制。
- 同一标书中可同时存在正文块、表格块、图片块、整页证据块。

示例：

| 分册/章节 | 推荐策略 |
|---|---|
| 技术标 - 投标响应总说明 | 标准正文型 |
| 技术标 - 生产制造能力 | 图片附件型 |
| 技术标 - 试验检测能力 | 图文增强型 |
| 技术标 - 技术参数响应 | 表格 + 正文 |
| 商务标 - 企业基本资格 | 图片附件型 |
| 商务标 - 承诺函 | 标准正文型 |
| 商务标 - 项目业绩 | 图文增强型或图片附件型 |

适合场景：

- 技术标需要大量产品、生产、检测图片。
- 商务标需要大量证照、合同、业绩扫描件。
- 部分章节仍必须保留正式文字和表格。
- 客户对不同分册有不同排版要求。

## 7. 为什么需要三种图片相关模式

如果只做一个简单的“图片型标书”开关，会带来明显问题：

1. 无法区分“多插图”和“正文主体全部图片”。
2. 容易影响当前成熟的文字型标书导出。
3. 不利于解释不同客户、不同省份、不同招标文件的差异。
4. 无法按章节精细控制，后续维护成本会升高。

因此建议用三种模式表达不同强度：

| 模式 | 图片使用强度 | 正文占比 | 实施难度 | 推荐优先级 |
|---|---:|---:|---:|---:|
| 图文增强型 | 中 | 高 | 低 | 第一优先级 |
| 图片附件型 | 高 | 低 | 中高 | 第二优先级 |
| 混合型 | 可配置 | 可配置 | 高 | 第三优先级 |

## 8. 功能需求

### 8.1 图片型标书资料包

目标：将客户整理的大量图片转为项目级可管理资料包。

功能点：

- 支持从企业资信库、企业产品库、企业知识库选择图片资产。
- 支持批量上传图片、PDF 扫描件、证书页、报告页。
- 支持按技术标、商务标、资格文件、附件材料分类。
- 支持查看资产数量、可用于正式标书数量、待复核数量。
- 支持搜索图片标题、来源文件、报告编号、产品型号。
- 支持标记推荐章节。
- 支持从图片包进入章节编排。

关键字段：

- 图片标题。
- 资料分类。
- 所属分册。
- 推荐章节。
- 来源文件。
- 来源页码。
- 质量状态。
- 是否允许进入正式标书。
- 中文题注。

### 8.2 章节图片包编排

目标：按章节组织图片顺序和版式。

功能点：

- 左侧展示技术标、商务标章节目录。
- 中间展示当前章节已选图片页。
- 支持拖拽调整图片顺序。
- 支持设置章节输出策略：正文为主、图文增强、图片为主、整页附件。
- 支持设置单页图片数量，例如 1 张、2 张、自动适配 A4。
- 支持设置图片题注策略。
- 支持设置是否纳入目录页码。
- 支持导出前强制复核。
- 支持标记待复核图片，不进入正式导出。

### 8.3 编辑器内图片块

目标：让图片型内容和文字型内容在编辑器里共存。

内容块建议：

- 正文块。
- 表格块。
- 图片块。
- 整页证据块。
- 附件说明块。

功能点：

- 当前章节中展示正文块和图片块。
- 支持插入图片包。
- 支持查看章节图片建议。
- 支持从知识库推荐相关图片。
- 支持图片块题注编辑。
- 支持图片块移动、删除、替换。
- 支持输出模式切换时保留同一套内容块。

### 8.4 导出模式选择

目标：在导出 DOCX 前明确选择输出策略。

功能点：

- 支持选择标准正文型、图文增强型、图片附件型、混合型。
- 展示预计页数、图片数量、正文页数。
- 展示导出前检查结果。
- 展示图片型标书预览缩略图。
- 支持仅预览和正式导出。
- 支持记录导出任务 metadata。

导出前检查：

- 是否只使用泰昌企业事实资产。
- 是否存在待复核图片。
- 是否存在低清晰度图片。
- 是否误用辽宁招标资料图片。
- 是否误用河北豪乾参考稿图片。
- 图片题注是否为中文正式名称。
- 目录、页眉页脚、页码字段是否刷新。

### 8.5 图片质量门禁

正式导出前必须增加图片质量门禁。

门禁规则：

- `formal_bid_ready` 才允许进入正式 DOCX。
- `knowledge_only` 仅可用于问答或参考，不进入正式标书。
- `review_only` 必须人工确认后才能导出。
- `restricted` 禁止导出。
- MinerU 局部切图、二维码、印章、签名、页脚、局部表格单元格不得自动进入正式标书。
- PDF 证书、报告、合同类资料优先整页渲染为图片。
- 产品实物、生产线、检测设备等优先使用客户原始高清照片。

### 8.6 导出审计

每次导出应记录：

- 项目 ID。
- 导出模式。
- 模板 ID。
- 分册范围。
- 章节输出策略。
- 候选图片数。
- 选中图片数。
- 成功插入图片数。
- 跳过图片数。
- 失败图片数。
- 跳过原因。
- 是否刷新 Word 字段。
- 是否通过图片来源门禁。
- 是否存在格式告警。

## 10. 数据设计建议

### 10.1 项目图片包

建议新增项目级图片包概念，绑定项目、分册、章节和图片资产。

核心字段：

| 字段 | 说明 |
|---|---|
| package_id | 图片包 ID |
| project_id | 项目 ID |
| volume_type | 技术标、商务标、资格文件、附件材料 |
| section_id | 绑定章节 ID |
| asset_id | 图片资产 ID |
| sort_order | 章节内排序 |
| caption | 正式中文题注 |
| layout_type | 单图、双图、整页 |
| include_in_toc | 是否纳入目录 |
| quality_status | 质量状态 |
| review_status | 复核状态 |

### 10.2 章节输出策略

建议为章节增加输出策略，而不是为整个项目硬编码一种模式。

核心字段：

| 字段 | 说明 |
|---|---|
| section_id | 章节 ID |
| presentation_mode | standard_text / image_enhanced / image_attachment / mixed |
| text_policy | 正文保留策略 |
| image_policy | 图片插入策略 |
| caption_policy | 题注策略 |
| page_layout_policy | A4 排版策略 |
| require_review | 是否导出前强制复核 |

### 10.3 内容块模型

建议将章节内容抽象为块：

```text
章节内容 = 正文块 + 表格块 + 图片块 + 整页证据块 + 附件说明块
```

这样标准正文型、图文增强型、图片附件型、混合型都可以复用同一套底层内容，只是在导出时采用不同排版策略。

## 11. 技术实现建议

### 11.1 前端

建议模块：

- 图片型标书资料包页面。
- 章节图片包编排组件。
- 标书编辑器图片块扩展。
- 导出模式选择弹窗。
- 图片质量检查面板。

技术要求：

- 复用当前 Vite + React + Ant Design 5。
- 复用现有 `AppLayout`、`ModuleHeader`、`MetricCards`、表格、标签、上传组件。
- 保持后台工作台风格。
- 不引入复杂设计器。
- 图片编排 MVP 可先用列表排序，后续再升级拖拽。

### 11.2 后端

建议能力：

- 图片包 CRUD。
- 章节图片绑定。
- 图片顺序保存。
- 章节输出策略保存。
- 图片质量门禁 API。
- 导出任务 metadata 记录。
- DOCX 导出按模式处理图片块。

### 11.3 DOCX 导出

导出链路仍应保持：

```text
build_project_bid_markdown
-> convert_md_to_word
-> refresh_docx_fields_with_soffice
```

新增点：

- 根据导出模式构建不同 Markdown 或中间结构。
- 图片附件型需要支持连续图片页。
- 整页证据页需要控制 A4 尺寸、边距和题注。
- 图片过多时需要控制压缩、分页和文件大小。
- 导出后必须审计 DOCX XML 或导出 metadata。

## 12. MVP 范围建议

### 12.1 第一阶段：图文增强型

目标：在当前正文型标书基础上增加更多图片。

范围：

- 从现有资产库选择图片。
- 按章节插入图片。
- 导出时统计图片候选、选中、插入、失败数量。
- 增加图片来源门禁。

优点：

- 改动小。
- 风险低。
- 可以快速给客户看到效果。

### 12.2 第二阶段：图片附件型

目标：支持大量图片连续编排。

范围：

- 项目图片包。
- 章节图片排序。
- 图片题注。
- 整页证据页。
- 导出前复核。
- 图片附件型 DOCX 导出。

优点：

- 直接满足客户参考新疆标书的需求。
- 可承接客户正在整理的大量图片。

### 12.3 第三阶段：混合型

目标：按分册、章节自由设置输出策略。

范围：

- 章节级策略配置。
- 不同分册独立导出策略。
- 图片块和正文块统一管理。
- 更细的预览和审计能力。

优点：

- 最符合长期真实投标场景。
- 可扩展到不同省份、不同客户、不同标书风格。

## 13. 验收标准

### 13.1 功能验收

- 可以创建项目图片包。
- 可以把图片绑定到技术标或商务标章节。
- 可以调整章节内图片顺序。
- 可以选择导出模式。
- 可以导出包含大量图片的 DOCX。
- 可以查看导出前检查结果。
- 可以查看导出后的图片插入统计。

### 13.2 质量验收

- 正式 DOCX 只使用泰昌企业事实图片。
- 不误用辽宁招标资料图片。
- 不误用河北豪乾参考稿图片。
- 图片题注为中文正式名称。
- 图片页 A4 内不变形、不溢出。
- 目录、页眉页脚、页码正常。
- 文件体积在可接受范围内。
- 低质量图片不会默认进入正式导出。

### 13.3 回归验收

- 标准正文型导出能力不受影响。
- 原有技术标、商务标文字生成流程不受影响。
- 原有 DOCX 导出格式不退化。
- 图片型模式关闭时，系统行为与当前默认模式一致。

## 14. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 图片质量不稳定 | 正式标书观感差 | 增加质量等级、人工复核和导出门禁 |
| 文件体积过大 | 下载、打开、传输变慢 | 图片压缩、分册导出、限制单次导出图片数量 |
| 图片来源混乱 | 企业事实错误、客户信任受损 | 严格 metadata 过滤，只允许泰昌企业事实资产 |
| 客户理解为“一键自动排好所有图片” | 预期过高 | 明确 MVP 先支持半自动编排和人工确认 |
| 后期文字修改困难 | 交付效率下降 | 保留标准正文型和图文增强型，不强制全部图片化 |
| DOCX 分页不稳定 | 正式文件观感差 | 建立真实导出链路验证和 XML 审计 |

## 15. 推荐结论

建议不要把该需求理解为“替换当前文字型标书”，而应理解为“在现有标书生成系统上增加图片型编排和导出能力”。

推荐路线：

1. 保留当前标准正文型作为默认模式。
2. 优先开发图文增强型，快速增强现有标书观感。
3. 在客户图片资料整理完成后，开发图片附件型，支持大量图片连续编排。
4. 最后沉淀为混合型，支持按技术标、商务标、资格文件和章节灵活控制。

对客户可说明：

> 系统不会放弃当前已经验证过的文字型标书能力，而是在此基础上增加图片型标书输出。客户既可以继续生成大量正式正文，也可以把泰昌整理好的图片、证书、报告、扫描件按章节编排进技术标和商务标，最终按不同模式导出正式 DOCX。
