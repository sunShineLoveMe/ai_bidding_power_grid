## 一、执行范围

本轮建立 P0-06 可审计审批机制，生成中文 Excel 审批表、证据分组、候选明细、自动阻断/仅参考清单、批准决定清单和增量入库候选清单。

本轮不代替客户做事实确认，不默认批准任何候选，不连接或写入数据库，不修改 RAG、metadata 或 DOCX 选图。

## 三、审批门禁覆盖

- 无人工批准不生成增量入库候选；
- 仅填写“批准”但缺少核验证据会失败；
- 受限/敏感、过期证书、产品不明、时效未核验会失败；
- 正式资产必须存在独立原始证据，历史标书本身不能替代原件；
- 参数表必须走结构化抽取；
- 用户可见名称必须使用中文正式表达；
- 审批表候选集合被篡改时阻断全部批准输出。

## 四、RAG 与 DOCX 门禁结论

本轮只生成离线审批工具和只读审批材料，正式增量入库候选仍为 0；没有修改数据库、正式资产 metadata、RAG 召回或 DOCX 资产选择。因此本轮不重复执行 Base + 泰昌专项全量召回门禁、真实 stream 或 DOCX 导出。

泰昌资料管理人员完成审批且实际执行入库或 metadata 更新后，必须执行标准增量回归门禁、真实 `/api/knowledge/search/stream` 抽样；涉及配图时必须执行正式 DOCX 导出及 XML 审计。

## 五、当前状态

P0-06 的技术准备已经完成，但业务任务保持进行中。阻塞条件不是程序错误，而是尚未取得泰昌资料管理人员对 461 条候选的审批结论和原始证据确认；在收到审批表前，不得把本任务标记为完全完成，也不得进入正式增量入库。
