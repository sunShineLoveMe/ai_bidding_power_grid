# Run 4 附：客户资料写作 parent 回溯抽查

> 批次：`customer_jx_sx_20260602_p1`
> 时间：2026-06-02
> 范围：`main_tender_file`、`contract_general_terms`、`contract_special_terms`

## 目的

确认写作场景 child 命中后回溯到的 parent 是否具备可用上下文，重点检查：

- parent 是否只是章节标题；
- parent 长度是否过短或过宽；
- 合同/招标文件章节边界是否能支撑正文写作引用。

## 发现与处理

刷新入库前，数据库中存在少量纯标题 parent，例如：

- `第一章 招标公告`
- `第二章 投标人须知`
- `第三章 评标办法（综合评估法）`

这些 parent 不参与 embedding，但会污染 parent 统计，并可能在极端情况下回溯到信息量不足的上下文。

处理：

- 在 `backend/rag/chunking.py` 中新增标题-only parent/child 过滤；
- 新增 `tests/test_rag_chunking.py`，覆盖主招标文件和合同条款的标题-only 分块回归；
- 使用修复后的分块器刷新 `customer_jx_sx_20260602_p1` staging 入库。
