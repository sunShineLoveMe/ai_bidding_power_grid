# 国家电网投标系统 MVP 改造与阿里云上线成本评估报告

> 评估日期：2026-05-07  
> 评估对象：现有 AI 招投标系统从水利行业场景改造为国家电网供应商投标场景  
> 目标形态：单企业部署版 MVP，生产环境部署在阿里云  
> 客户预算：约 25 万元，且倾向“只少不多”  
> 评估口径：按“能真实上线给企业使用”的成本估算，不按纯演示 Demo 估算

---

## 一、一句话结论

**25 万可以做一个“可演示、可试用、单企业低并发 MVP”，但不足以覆盖一个稳定、可运维、可长期生产使用的国家电网投标系统。**

如果严格控制范围，25 万的合理交付边界是：

- 保留现有招标文件解析、AI 解读、大纲生成、正文生成、Word 导出主链路；
- 将行业知识、提示词、分册结构、资质库、产品库从水利改为电力/国网供应商场景；
- 做最小安全加固、Docker 化、阿里云单企业部署；
- 不做复杂多人协同、不做完整权限体系、不做深度国网平台接口对接、不做高可用集群。

**真实建议报价区间：**

| 交付等级 | 一次性实施费用 | 首年云资源与第三方服务 | 首年真实总成本 | 结论 |
|---|---:|---:|---:|---|
| 演示验证版 | 12-18 万 | 1.5-3 万 | 13.5-21 万 | 可演示，不建议生产 |
| 极简生产 MVP | 22-28 万 | 2.5-5 万 | 24.5-33 万 | 勉强可上线，范围必须严格锁死 |
| 推荐生产 MVP | 32-45 万 | 4-8 万 | 36-53 万 | 更接近真实可用 |
| 稳定企业版 | 55-85 万 | 8-15 万 | 63-100 万 | 可长期运营和迭代 |

**因此：客户 25 万预算不是完全不能做，但必须按“极简生产 MVP”切范围，并明确不包含长期运维、深度定制、高可用和复杂安全合规。**

## 二、现有项目迁移到电网场景的可复用度

现有项目并不是从零开始，已经有较完整的 AI 标书主流程。迁移到国家电网供应商投标场景时，可复用部分较多，但行业内容需要重做。

### 2.1 可直接复用的能力

| 模块 | 可复用度 | 说明 |
|---|---:|---|
| 招标文件上传与解析 | 80% | PDF/DOCX/TXT、MinerU/OCR、原生解析可复用 |
| AI 招标解读 | 60% | 框架可复用，国网字段、评分点、风险项规则需重写 |
| 章节大纲生成 | 60% | 大纲生成框架可复用，分册结构需电力化 |
| 标书正文生成 | 70% | 生成链路可复用，Prompt、企业画像、术语库需重做 |
| 合规覆盖检查 | 60% | 检查框架可复用，国网条款分类和否决项规则需补充 |
| 企业资信库 | 70% | 上传、分类、检索可复用，资质类型需改成电力供应商资质 |
| 产品库 | 70% | 图片/产品资料管理可复用，产品分类需改成电力设备/服务 |
| Word 导出 | 75% | 导出链路可复用，但国网格式、分册、封面、目录需调整 |
| 阿里云部署 | 40% | 当前无 Docker/CI/CD/生产部署脚本，需要补齐 |

### 2.2 不能直接复用、必须改造的部分

| 改造项 | 原因 | 工作量判断 |
|---|---|---:|
| 国网行业知识库 | 水利知识库不能支撑电网投标 | 中 |
| 国网招标文件解析规则 | 国网项目字段、评分办法、资格要求不同 | 中 |
| 电力分册结构 | 技术规范响应、商务偏差、货物清单、资质业绩等结构不同 | 中 |
| 电力产品库 | 设备、材料、服务类供应商分类完全不同 | 中 |
| 企业资质库 | 需要营业执照、信用、ISO、CCC/型式试验、业绩、授权、检测报告等 | 中 |
| Word 模板 | 国网投标文件正式格式需重新校准 | 中 |
| 安全与部署 | 当前项目企业生产能力不足 | 中高 |

## 三、国家电网 MVP 第一版建议范围

### 3.1 MVP 应该做什么

第一版目标应该是：**帮助单一供应商完成国网类招标文件解读、标书初稿生成、资料引用和 Word 导出。**

建议 MVP 包含：

1. 招标文件上传与解析
2. 国网招标文件要点解读
3. 资格要求、否决项、评分项、技术规范自动提取
4. 自动生成投标文件分册大纲
5. 单章/批量生成标书正文
6. 企业资信库、电力产品库资料引用
7. 条款响应率检查
8. Word 导出
9. 单企业部署到阿里云
10. 最小安全加固：登录/API Key、CORS 限制、错误脱敏、上传限制

### 3.2 MVP 不建议做什么

25 万预算下，以下内容不建议纳入第一版：

| 不建议纳入 | 原因 |
|---|---|
| 多企业、多租户 | 会显著增加权限、数据隔离和运维复杂度 |
| 多人协同编辑 | 需要锁、版本、冲突处理，超出 MVP |
| 国网电子商务平台接口直连 | 存在账号、验证码、风控、合规风险 |
| 自动报价/清单计价深度计算 | 风险高，业务校验复杂 |
| 完整审计日志体系 | 可做基础日志，完整审计放二期 |
| 高可用集群 | 单企业 MVP 可先单机或轻量双机 |
| 全量测试体系 | 第一版只做主链路验收测试和冒烟测试 |
| 等保/密评级安全合规 | 预算远远不够 |

## 六、阿里云资源成本估算

> 说明：阿里云价格会随地域、活动、计费方式变化，以下为工程估算。正式报价应以阿里云控制台实际下单价格为准。  
> 参考依据：阿里云官方文档显示，ECS 支持包年包月/按量/抢占式计费；RDS PostgreSQL 包含实例规格、存储、备份等计费项，Serverless PostgreSQL 按 RCU 和存储计费；OSS 按存储、请求、流量等计费；ALB 由实例费、LCU 和公网流量等组成。

### 6.1 极简生产 MVP 配置

适合：单企业、1-5 个内部用户、低并发、每天少量标书生成。

| 资源 | 建议配置 | 年成本估算 |
|---|---|---:|
| ECS 应用服务器 | 4 核 8G / 8 核 16G，部署 Flask、前端、任务进程 | 6000-18000 |
| 数据库 | 自建 PostgreSQL + pgvector，或低配 RDS PostgreSQL | 5000-18000 |
| OSS | 100-500GB 标书、资料、导出文件 | 500-3000 |
| 公网带宽/EIP | 5-10Mbps 或按量流量 | 1500-6000 |
| SSL/域名 | 免费证书或基础证书 | 0-2000 |
| 备份存储 | 数据库快照、OSS 备份、本地备份 | 1000-4000 |
| 日志与监控 | 基础云监控，少量日志服务 | 0-3000 |
| **小计** |  | **1.4-5.4 万/年** |

### 6.2 推荐生产 MVP 配置

适合：正式给客户内部使用，要求相对稳定，有基础备份和故障恢复。

| 资源 | 建议配置 | 年成本估算 |
|---|---|---:|
| ECS 应用服务器 | 2 台 4 核 8G 或 1 台 8 核 16G | 1.2-3.5 万 |
| RDS PostgreSQL 或自建独立 DB | 2 核 4G / 4 核 8G，100-300GB | 1.2-4 万 |
| OSS | 500GB-1TB | 1000-6000 |
| ALB/Nginx/EIP | 简单负载或单机反代 | 2000-10000 |
| 备份与快照 | 数据库自动备份、文件备份 | 3000-10000 |
| 日志监控 | 云监控 + 简单日志服务 | 2000-8000 |
| **小计** |  | **3.4-10.9 万/年** |

### 6.3 AI 与 OCR 调用成本

| 服务 | 成本影响因素 | 月成本估算 |
|---|---|---:|
| DashScope/Qwen 文本生成 | 招标文件长度、章节数量、生成次数 | 500-5000 |
| Embedding 向量化 | 知识库大小、资料更新频率 | 100-1000 |
| Rerank | 检索问答频率 | 100-1000 |
| MinerU/OCR | PDF 页数、扫描件比例、解析频率 | 500-5000+ |

保守估计：

- 低频使用：**1000-3000 元/月**
- 正常使用：**3000-8000 元/月**
- 高频或大量扫描件：**8000 元/月以上**

**首年 AI/OCR 预算建议至少预留 2-6 万。**

## 七、25 万预算是否够

### 7.1 如果 25 万包含全部内容

如果 25 万包含：

- 需求分析
- 电网行业改造
- 开发
- 测试
- 阿里云部署
- 云资源
- AI/OCR 调用
- 售后运维

那么结论是：**不够。**

比较真实的首年成本：

| 成本项 | 低配 | 推荐 |
|---|---:|---:|
| 一次性开发实施 | 18-25 万 | 30-45 万 |
| 阿里云资源首年 | 2-5 万 | 4-10 万 |
| AI/OCR 首年 | 2-6 万 | 4-10 万 |
| 运维支持 | 2-5 万 | 6-12 万 |
| **首年合计** | **24-41 万** | **44-77 万** |

所以，25 万只能覆盖低配极限情况，且几乎没有风险缓冲。

### 7.2 如果 25 万只包含软件改造实施

如果客户自行承担阿里云资源、DashScope、MinerU/OCR 费用，25 万作为软件改造实施费，则可以做。

但必须明确：

- 第一版只做单企业；
- 不做多用户权限；
- 不做国网平台自动填报；
- 不做高可用；
- 不承诺所有国网招标文件都完美解析；
- 不承诺生成标书可直接投标，必须人工复核；
- 售后只包含 1-2 个月缺陷修复，不包含持续运营。

## 九、推荐实施计划

### 阶段 1：电网 MVP 业务适配

周期：2-3 周  
目标：让系统“像电网投标系统”，而不是水利系统换皮。

交付：

- 国网招标文件样本分析
- 电力行业分类体系
- 电力资信库/产品库字段
- 国网 Prompt 改造
- 分册大纲规则改造

### 阶段 2：核心链路改造

周期：3-4 周  
目标：跑通上传、解读、大纲、正文、合规、导出。

交付：

- 国网解读报告
- 电网分册大纲
- 章节正文生成
- 资信/产品资料引用
- Word 导出格式调整

### 阶段 3：阿里云生产部署

周期：1-2 周  
目标：可在客户阿里云环境稳定访问。

交付：

- Docker 化部署
- Nginx/HTTPS
- 数据库与文件存储
- 环境变量配置
- 基础备份
- 部署文档

### 阶段 4：样本验收与修复

周期：1-2 周  
目标：使用真实国网招标文件验收。

交付：

- 3 份样本端到端测试
- 问题修复
- 操作手册
- 验收清单

总周期：**7-11 周**

## 十、主要风险

### 10.1 业务风险

| 风险 | 影响 | 建议 |
|---|---|---|
| 国网招标文件类型差异大 | 大纲和正文质量不稳定 | MVP 先限定 1-2 类供应商场景 |
| 客户企业资料不完整 | AI 生成大量“待补充” | 项目启动前要求客户提供资料清单 |
| 标书正式性要求高 | AI 初稿不能直接投标 | 合同中明确“辅助生成，人工复核” |
| 报价/清单复杂 | 容易产生商务风险 | 第一版不做自动报价决策 |

### 10.2 技术风险

| 风险 | 影响 | 建议 |
|---|---|---|
| 大 PDF/OCR 不稳定 | 解读失败或耗时长 | 保留手动导入和重试机制 |
| LLM 输出不稳定 | 正文质量波动 | 增加模板、规则兜底、人工编辑 |
| pgvector/RDS 兼容性 | 向量检索部署受限 | 优先验证阿里云 PostgreSQL 扩展支持；不行则自建 PostgreSQL |
| Word 格式细节多 | 反复修改 | 限定第一版模板边界 |
| 25 万无缓冲 | 需求变更必超支 | 必须合同锁范围 |

## 十一、报价建议

### 11.1 对客户的建议报价

如果客户预算固定 25 万，建议拆成：

| 项目 | 金额 |
|---|---:|
| 电网业务适配与 Prompt 改造 | 6 万 |
| 核心功能改造 | 8 万 |
| 资信库/产品库/知识库改造 | 4 万 |
| Word 导出与样式调优 | 2 万 |
| 阿里云部署与安全加固 | 3 万 |
| 测试验收与文档 | 2 万 |
| **合计** | **25 万** |

但这份报价必须附带限制条件：

- 云资源费客户另付；
- DashScope/MinerU/OCR 费用客户另付；

- 新增大功能另行报价。

| 推荐上线版 | 35-45 万 | 真实上线、可持续使用 |
| 企业稳定版 | 60 万以上 | 有权限、备份、监控、审计、长期维护 |

## 十二、最终建议

### 是否建议接 25 万项目？

**可以接，但必须重写交付边界。**

不建议承诺“完整电网投标生产系统”。  
建议承诺“国家电网供应商投标辅助生成 MVP 系统”。

### 最佳合同表述

建议合同中使用以下定位：

> 本项目为面向单一企业的国家电网供应商投标辅助生成 MVP 系统，目标是实现招标文件解析、投标文件初稿生成、企业资料引用、条款响应检查和 Word 初稿导出。系统生成内容仅作为投标文件编制辅助材料，正式投标前需由客户业务人员、法务人员和投标负责人审核确认。

### 最终判断

| 问题 | 判断 |
---|---|
| 现有项目能否改成电网场景？ | 能，基础链路可复用 |
| 是否适合国网供应商投标？ | 适合做辅助生成，不适合第一版做全自动投标 |
| 25 万能不能做？ | 能做极简 MVP，但不能做完整生产级 |
| 真实上线成本是多少？ | 首年低配 24-41 万，推荐 44-77 万 |
| 建议周期 | 7-11 周 |
| 最大风险 | 范围失控、资料不全、Word 格式反复、AI/OCR 成本不可控 |

**最终建议：若客户预算固定 25 万，必须采用“范围锁死 + 云资源另付 + 只做单企业 MVP + 明确人工复核责任”的交付方式。否则该项目极易亏损并形成长期维护负担。**
