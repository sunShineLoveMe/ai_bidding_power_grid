## 4. RAG 入库与模板参考分工

| 资料类型 | 是否进 RAG | 是否做模板参考 | 处理方式 |
| --- | --- | --- | --- |
| 主招标文件 DOCX | 是，高优先级 | 是，高优先级 | MinerU/原生 DOCX 双路抽取；按章、节、表格切片；保留页码、章节号、批次、省份、包号 |
| 招标公告 DOCX | 是，高优先级 | 是，中优先级 | 抽取招标条件、资格要求、投标文件要求、平台规则、否决风险、时间节点 |
| 投标注意事项 | 是，高优先级 | 否 | 单独标为 `risk_checklist`，用于否决项和合规检查 |
| 技术规范书 DOC/DOCX | 是，最高优先级 | 是，高优先级 | 按“通用部分/专用部分/技术参数/供货一览表/投标人保证值”切片；表格必须保留结构 |
| 合同通用条款/专用条款 | 是，中高优先级 | 是，中优先级 | 用于商务响应、偏差识别、履约风险，不直接生成大段合同原文 |
| 货物清单 XLSX | 不做普通向量 RAG | 是，结构参考 | 走结构化解析，入库为物料、包号、数量、单位、技术规范关联字段 |
| 法规 Markdown | 是 | 否 | 直接按标题/条款切片，作为合规依据 |
| 法规 PDF | 有条件 | 否 | MinerU 抽取后只入摘要、条款索引和关键条款，避免噪声 |
| 标准规范 Markdown | 是 | 否 | 作为标准名称、适用场景、引用边界知识 |
| 标准规范 PDF | 有条件 | 否 | 优先入标准目录、适用范围、引用方式；不建议全量入库大段标准原文 |
| 自建标准话术 | 是 | 是 | 直接入库，作为正文生成、补写和检查清单 |
| `.zip/.rar/.sign/.zb` | 否 | 否 | 仅保留原始归档和追溯，不参与 RAG |

## 5. 建议的 RAG 分类体系

建议新增或规范以下分类字段，不再混用旧行业分类：

| 分类 | 用途 |
| --- | --- |
| `sgcc_tender_file` | 客户主招标文件、采购文件、投标人须知、评标办法、投标文件格式 |
| `sgcc_tender_notice` | 招标公告、采购公告、投标注意事项 |
| `sgcc_technical_spec` | 技术规范书、技术参数表、供货范围、试验要求 |
| `sgcc_contract_terms` | 合同通用条款、专用条款、合同协议书模板 |
| `sgcc_goods_list` | 货物清单结构化数据，不走普通文本向量 |
| `sgcc_policy_regulation` | 法律法规、国网招标活动和供应商管理制度 |
| `sgcc_standard_catalog` | GB/DL/Q-GDW 标准目录、标准适用场景和引用方式 |
| `sgcc_response_phrase` | 自建资格、商务、技术、质量安全环保话术 |
| `sgcc_compliance_checklist` | 否决项、格式检查、平台规则、签章加密上传检查 |

每个分片建议保留元数据：

- `province`：江西、山西
- `batch_no`：如 `1826AA`、`0526AB`
- `package_no`：包1
- `material_category`：铁构件、接地铁、镀锌扁钢、不锈钢电缆支架
- `doc_role`：招标文件、公告、技术规范、合同、货物清单、注意事项
- `chapter`、`section`、`table_title`
- `source_file`、`source_path`
- `effective_year` 或 `issue_year`
- `qualification_mode`：资格预审、资格后审

## 6. 模板与格式标准判断

从客户 DOCX 抽样看，江西、山西主招标文件具有高度一致的页面设置：

- 页面：A4，`11850 x 16783` twips
- 主招标文件页边距：上/下 `1134` twips，左/右 `1800` twips，约等于上/下 2.0 cm、左/右 3.17 cm
- 合同条款页边距：上/下 `1440` twips，左/右 `1803` twips，约等于上/下 2.54 cm、左/右 3.18 cm
- 默认东亚字体：`宋体`
- 正文样式多见：`等线`，字号 `21` half-points，即 10.5 pt
- 一级标题：江西主文件中为 `宋体`，字号 `44` half-points，即 22 pt
- 二级标题：江西主文件中出现 `Microsoft JhengHei`，字号 `32` half-points，即 16 pt

实施结论：

1. 国网不同省公司、不同采购工具生成的 DOCX 不应假设存在唯一固定字体标准，应以当批招标文件和投标文件格式要求为最高依据。
2. 系统应把主招标文件 DOCX 作为“样式模板来源”，自动抽取 A4、页边距、默认字体、标题层级、表格样式，再映射到投标文件导出。
3. 默认兜底模板可采用：A4、正文 10.5 pt、中文宋体/等线、英文 Times New Roman、左/右约 3.17 cm、上/下约 2.0 cm，表格使用细边框、表头加粗。
4. 如果招标文件明确要求电子投标工具、PDF、TP 工程文件、签章、加密上传，应优先满足电子投标平台要求，而不是仅追求 Word 版式。

## 7. 实施路线

### 阶段一：资料清洗与解析

1. 保留客户原始 ZIP，作为不可修改归档。
2. 对主招标文件、公告、技术规范、合同 DOCX/DOC 批量跑 MinerU 或原生 DOCX 解析。
3. 对 XLSX 货物清单走结构化解析，不做普通 Markdown 切片。
4. 对 `.sign/.zb/.zip/.rar` 标记为 `archive_only`。
5. 为每个解析产物生成 `manifest.json`，记录来源文件、hash、解析方式、文件角色、批次和包号。

### 阶段二：知识库入库

1. 先入库 `04_standard_phrases`，保证生成链路有稳定话术。
2. 入库客户主招标文件、公告、投标注意事项、技术规范书。
3. 入库法规 Markdown 和已人工确认的法规 PDF 摘要。
4. 入库标准目录和标准引用说明，不批量灌入大段标准全文。
5. 建立客户标书专属 collection 或 project scope，避免江西/山西批次之间互相污染。

### 阶段三：模板库建设

1. 从江西、山西主招标文件提取样式，形成 `sgcc_docx_style_profile`。
2. 从“第六章 投标文件格式”、技术规范书参数表、合同文件中提取模板片段。
3. 建立模板用途标签：资格响应、商务响应、技术响应、偏差表、报价/货物清单、合同响应、附件。
4. Word 导出时按招标文件样式 profile 覆盖默认样式。

### 阶段四：质量验证

1. 建立 30-50 条国网招投标 Base 测试问题，覆盖资格、否决项、技术参数、合同、报价、平台规则。
2. 每次入库后跑检索评估：召回来源是否来自正确批次、正确文件、正确章节。
3. 对生成正文做人工复核清单：是否引用错省份、错批次、错物料、错资格模式。
4. 对 DOCX 导出做版式检查：字体、字号、页边距、标题层级、表格、目录和页码。

## 8. 当前最优先的下一步

1. 对两批客户标书的 DOCX/DOC 文件批量跑 MinerU，并把产物落到 `parsed_outputs/sgcc_customer_tenders/` 或同等专用目录。
2. 生成客户标书解析清单：每个文件的 `full.md`、表格数量、章节层级、是否解析成功。
3. 把主招标文件、公告、投标注意事项、技术规范书作为第一批客户 RAG 入库对象。
4. 把货物清单 XLSX 单独解析成结构化表，不进入普通向量库。
5. 抽取江西、山西主招标文件样式，形成投标文件导出的国网样式 profile。
